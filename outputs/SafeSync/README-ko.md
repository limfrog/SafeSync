# SafeSync

SafeSync는 Windows에서 파일 변화 또는 지정한 시간에 맞춰 로컬 폴더, 외장 드라이브, NAS/네트워크 드라이브, Dropbox 및 Google Drive 동기화 폴더로 자동 백업하는 프로그램입니다.

Windows 10/11의 기본 Windows PowerShell 5.1만 있으면 실행할 수 있으며 별도 런타임 설치가 필요하지 않습니다.

## 설치 및 제거

`SafeSync-Setup.exe`를 실행한 뒤 **설치**를 누르세요. 관리자 권한 없이 현재 사용자 계정에 설치합니다. 앱 파일은 `%LOCALAPPDATA%\Programs\SafeSync`에, 설정과 인증 정보는 별도의 `%LOCALAPPDATA%\SafeSync`에 저장됩니다.

시작 메뉴에 **SafeSync**와 **SafeSync 제거**가 추가됩니다. 바탕 화면 바로 가기는 설치 화면에서 선택할 수 있습니다. 설치 완료 후 실행 옵션을 켜 두면 창 대신 알림 영역에 SafeSync 아이콘이 나타납니다.

업데이트 전에 진행 중인 백업이 있다면 완료될 때까지 기다린 다음, 알림 영역의 **프로그램 종료**로 앱을 완전히 종료하고 새 설치 EXE를 실행하면 됩니다. 설정, 클라우드 연결 정보와 백업 파일은 그대로 유지됩니다. 설치 파일은 압축을 푼 뒤 각 파일의 SHA-256을 검증하며, 교체 실패 시 이전 앱으로 되돌립니다. 중단된 설치의 복구 기록은 다음 설치 실행 시 처리합니다.

제거는 Windows **설정 → 앱 → 설치된 앱 → SafeSync → 제거** 또는 시작 메뉴의 **SafeSync 제거**로 진행합니다. 실행 파일과 앱이 만든 바로 가기·자동 시작 등록만 제거하며, 설정·인증 정보·로그·실제 백업 파일·SafeSync 휴지통은 삭제하지 않습니다. 설치 폴더에 직접 추가한 다른 파일도 남깁니다. 제거 보조 EXE 하나가 Windows 임시 폴더에 남을 수 있으며, 실행이 끝난 뒤 Windows 임시 파일 정리로 삭제할 수 있습니다.

현재 개인용 빌드는 코드 서명 인증서가 없는 상태입니다. 다운로드한 EXE는 Windows SmartScreen 경고 또는 일부 보안 정책의 차단 대상이 될 수 있습니다. 보안 기능을 끄는 방식은 권장하지 않습니다. 관련 안내: [Microsoft SmartScreen과 코드 서명](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/smartscreen-reputation).

ZIP은 설치 없이 사용할 수 있는 별도 배포본입니다. ZIP 안의 `Uninstall.exe`는 설치된 앱 전용이므로, ZIP 실행본은 앱을 종료한 뒤 압축을 푼 폴더만 정리하면 됩니다.

## 실행

1. 시작 메뉴의 **SafeSync** 또는 압축을 푼 `SafeSync.exe`를 더블 클릭하면 창을 띄우지 않고 Windows 알림 영역에서 실행됩니다. 기존 `Start SafeSync.cmd`도 사용할 수 있습니다.
2. 알림 영역의 SafeSync 아이콘을 더블 클릭하거나, 아이콘을 오른쪽 클릭한 뒤 **SafeSync 열기**를 선택합니다.
3. **작업 추가**를 눌러 원본과 백업 위치를 지정합니다.
4. **파일 변경 시** 또는 **매일 정해진 시간** 중 하나를 고릅니다.
5. 창의 닫기 버튼을 눌러도 알림 영역에서 계속 작동합니다. 완전히 끝내려면 알림 영역 아이콘을 오른쪽 클릭하고 **프로그램 종료**를 선택합니다.

목록에서 원하는 작업을 선택하고 **일시정지**를 누르면 그 작업의 파일 변경 백업과 예약 백업만 멈춥니다. 다른 작업은 계속 실행되며, 일시정지 상태는 프로그램을 다시 실행하거나 새 버전을 설치해도 유지됩니다. 일시정지 중에도 SafeSync가 실행되어 있으면 변경 경로를 기록합니다. **다시 시작**을 누르면 파일 변경 방식은 잠시 후, 예약 방식은 다음 예약 시간에 저장된 재개 지점부터 백업을 이어갑니다. 백업 중 일시정지하면 현재 파일이 다시 한 번 안전하게 비교될 수 있지만, 이미 완료된 파일을 다시 업로드하지는 않습니다. 작업 중단 시 최대 몇 개의 최근 파일은 안전을 위해 재시도합니다.

**프로그램 종료**를 선택하면 실행 중인 백업 작업도 함께 중지하고 SafeSync 관련 프로세스를 모두 끝냅니다. 파일 교체 보호 기록과 임시 사본은 다음 실행 때 복구되므로 기존 정상 백업 파일은 보존됩니다. 백업을 끝까지 완료하려면 진행 상황이 사라진 뒤 종료하세요.

백업이 실행되는 동안 기본 창이 열려 있으면 **백업 비교 및 충돌 처리** 창이 자동으로 표시됩니다. 처음에는 기본 창 옆의 사용 가능한 공간에 배치되며, 이후에는 사용자가 원하는 위치로 자유롭게 옮길 수 있습니다. 기본 창을 움직이거나 크기를 바꿔도 진행 창의 위치를 강제로 되돌리지 않습니다. 위쪽에는 원본과 백업 위치가 좌우로 표시되고, 작업 이름, 현재 확인 중인 폴더, 처리 중인 파일과 크기, 완료한 파일 수와 전체 파일 수, 진행률을 확인할 수 있습니다. Dropbox와 Google Drive는 계정 연결, 이전 전송 복구 확인, 클라우드 파일 목록 확인, 파일 비교, 임시 업로드, 체크섬 검증, 안전한 교체, 휴지통 정리 단계를 구분해 표시합니다. 여러 작업을 동시에 실행하면 같은 창에 각각 표시됩니다. 백업 중에는 알림 영역의 SafeSync 아이콘 화살표가 회전하는 프레임으로 표시됩니다. 창 최소화·닫기와 일반 알림은 시스템 경고음을 내지 않습니다. 기본 창을 닫아 알림 영역으로 보내면 진행 창도 숨겨지지만 백업은 계속되며, 기본 창을 다시 열면 진행 창도 다시 나타납니다.

기본 창이 최소화되었거나 알림 영역에 숨겨진 동안에는 오류와 충돌 창을 갑자기 띄우지 않습니다. 대신 알림 영역 아이콘이 경고 모양으로 바뀌고 기본 창의 **확인할 메시지** 버튼에 개수가 표시됩니다. SafeSync 창을 다시 열면 대기 중인 내용을 확인할 수 있습니다. 같은 파일의 해결되지 않은 오류나 충돌은 한 번만 알리며, 해당 파일이 정상적으로 백업된 뒤 같은 문제가 새로 발생하면 다시 알립니다. 이 알림 상태는 프로그램을 다시 실행해도 유지됩니다.

처음 실행한 뒤에는 기본적으로 Windows 로그인 시 자동 시작됩니다. 기본 창의 **도구 → 환경설정**에서 자동 시작, SafeSync 휴지통 보관기간, 창 최소화·알림 영역 이동 알림음, 백업 오류 알림음, 라이트·다크 화면 모드를 각각 바꿀 수 있습니다. Dropbox·Google Drive 클라우드 계정 연결도 관리할 수 있으며, 같은 창에서 파일 버전, 제작자, 이메일 정보도 확인할 수 있습니다.

작업 목록의 **원본 위치** 또는 로컬·네트워크 방식의 **백업 위치**를 더블클릭하면 해당 폴더가 Windows 탐색기에서 열립니다. Dropbox API와 Google Drive API 위치는 Windows 폴더가 아니므로 탐색기 대신 환경설정의 클라우드 계정과 작업 수정 화면에서 관리합니다.

## 파일 판단 규칙

- 경로, 만든 시간, 수정 시간, 크기가 같으면 건너뜁니다.
- 원본의 수정 시간이 더 최신이면 백업 파일을 교체합니다.
- 시간이 같은데 크기가 다르거나, 백업 위치의 파일이 더 최신이면 충돌로 기록합니다.
- 충돌 파일은 변경하지 않으며, 나머지 파일은 계속 백업합니다.
- 완료 후 같은 진행 창의 충돌 목록에서 원본·현재 백업의 크기와 수정 시간, 충돌 이유를 나란히 보여줍니다.

## 증분 스냅샷

SafeSync는 작업별 파일 스냅샷과 변경 대기열을 `%LOCALAPPDATA%\SafeSync\manifests`에 보관합니다. 앱이 실행 중일 때 Windows가 알려 주는 파일 경로를 대기열에 기록하므로, 자동 백업은 매번 원본과 백업 위치 전체를 검사하지 않고 변경된 파일과 이전에 실패한 파일만 처리합니다. 예약 작업도 실행 시각 전까지 발견된 변경 경로를 모아 두었다가 예약 시각에 처리합니다. 버전 1.5부터 **지금 백업**과 **모든 작업 백업**도 이 빠른 변경 목록을 사용합니다.

- 작업의 첫 백업과 마지막 전체 검사 후 7일 이상 지난 경우에는 전체 검사를 합니다. 사용자가 즉시 모든 파일을 다시 확인하려면 작업을 선택하고 **전체 검사**를 누릅니다.
- 파일 감시 정보가 넘치거나 원본·네트워크 위치가 끊겼다가 다시 연결되어 변경 범위를 확실히 알 수 없는 경우에도 안전을 위해 전체 검사로 전환합니다.
- NTFS 로컬 드라이브는 Windows USN Journal의 마지막 위치를 작업별로 저장합니다. 앱이 꺼져 있던 동안의 생성·수정·삭제·이름 변경 기록만 읽어 변경 파일을 대기열에 넣으므로, 짧은 종료 후에도 원본 전체를 다시 스캔하지 않습니다.
- USN Journal을 사용할 수 없는 네트워크·비NTFS 드라이브, Journal 초기화·기록 손실, 첫 실행, 7일 이상 지난 스냅샷에서는 시작 시 스냅샷과 원본의 경로·시간·크기를 대조하는 안전한 대체 방식을 사용합니다. 이 경우에만 해당 위치의 메타데이터를 다시 확인합니다.
- 유효한 스냅샷과 USN 위치가 있으면 앱을 다시 시작해도 저장된 실패 파일과 USN 변경 경로만 재시도합니다. 사용자가 즉시 모든 파일을 다시 확인하려면 작업을 선택하고 **전체 검사**를 누릅니다.
- 각 파일은 `BackedUp`, `Conflict`, `Failed` 상태로 저장됩니다. 복사·전송 오류가 난 파일은 `Failed`와 오류 내용이 유지되며, 새 변화가 없어도 다음 백업 대상에 자동으로 포함됩니다. 성공하면 `BackedUp`으로 바뀝니다.
- 충돌이 발견되면 **백업 비교 및 충돌 처리** 창에서 파일별로 **원본으로 덮어쓰기**, **기존 백업 이름 변경 후 복사**, **이번에는 변경 안 함** 중 하나를 선택할 수 있습니다. 원본으로 덮어쓰기를 선택해도 기존 백업 파일은 즉시 삭제하지 않고 SafeSync 휴지통에 보관한 뒤 검증된 원본 사본으로 교체합니다. 기존 백업 이름 변경 후 복사는 현재 백업 파일을 같은 폴더에 `.SafeSync-conflict-날짜`가 붙은 이름으로 남긴 뒤 원본을 정상 이름으로 복사하므로 두 파일을 직접 비교할 수 있습니다. 이 선택은 로컬·네트워크·Dropbox·Google Drive에 적용됩니다. 변경 안 함을 선택한 파일은 건드리지 않습니다.

전체 검사가 필요한 경우에는 PowerShell에서 파일마다 폴더를 반복해서 여는 대신 컴파일된 .NET 스캔 엔진이 파일 목록을 한 번에 수집합니다. 연결 폴더는 원본 폴더 밖으로 잘못 따라가지 않도록 제외합니다. Dropbox는 `list_folder` 변경 커서를, Google Drive는 `changes` 페이지 토큰을 스냅샷과 함께 보관하므로 최초 확인 뒤에는 작업 실행 시 마지막 확인 이후 바뀐 클라우드 항목만 조회합니다. 변경 기록을 읽은 직후 커서와 대기 파일을 먼저 저장하므로 중간에 재부팅되어도 같은 변경 기록을 처음부터 다시 받지 않습니다. Google Drive 변경 기록에 포함된 파일 정보는 그대로 재사용하고, 스냅샷과 다시 대조해야 하는 파일 정보는 최대 100개씩 묶어서 요청합니다. 긴 백업 도중 접근 토큰이 만료되면 자동으로 갱신한 뒤 해당 요청을 한 번 다시 시도합니다. 변경 커서가 만료되거나 유효하지 않으면 데이터 누락을 막기 위해 해당 실행만 자동으로 전체 검사로 전환합니다.

## 복사·전송 오류 방지

새 파일을 기존 백업 위에 직접 전송하지 않습니다. 먼저 임시 사본을 만들고 크기와 내용의 체크섬을 검사한 뒤에만 정상 백업으로 반영합니다. 이 보호는 항상 적용되므로 별도 설정이 필요 없습니다.

- **로컬·외장·네트워크·동기화 폴더:** 원본을 복사하는 동안 다른 프로그램의 쓰기를 제한하고, 임시 파일을 끝까지 기록한 뒤 다시 읽어 SHA-256을 비교합니다. 기존 파일이 있으면 Windows의 파일 교체 기능으로 새 파일을 반영하면서 이전 버전을 `.safesync-trash`에 보관합니다. 교체 후에도 내용이 일치하는지 확인합니다.
- **Dropbox API:** 임시 클라우드 폴더에 업로드하고 서버의 파일 크기와 Dropbox content hash를 비교합니다. 확인된 파일만 정상 위치로 옮깁니다. 기존 백업을 휴지통으로 옮긴 뒤 새 파일 배치가 실패하면 이전 파일을 원위치로 복구합니다.
- **Google Drive API:** 임시 클라우드 폴더에 업로드하고 서버의 파일 크기와 SHA-256을 비교합니다. SHA-256이 제공되지 않으면 MD5를 사용하며, 체크섬이 없거나 다르면 반영하지 않습니다. 새 파일이 정상 위치에 배치된 것을 확인한 뒤 기존 파일을 휴지통으로 옮깁니다.
- 복사 도중 원본이 변경되거나 파일이 사용 중이면 해당 파일은 오류로 기록하고 이전 백업을 보존합니다. 같은 작업의 다른 파일은 계속 백업합니다.
- 교체 직전에는 복구 기록을 남깁니다. 프로그램 종료나 네트워크 단절로 복구가 미완료되면 다음 백업 실행에서 기록을 확인해 이전 파일 복원 또는 검증된 교체 마무리를 시도합니다. 복구가 필요한 이전 버전은 정리가 완료되기 전까지 자동 삭제하지 않습니다.
- 동일한 백업 폴더를 대상으로 하는 작업이 동시에 실행되면 하나만 실행하고 나머지는 오류로 알립니다. 먼저 실행한 작업이 끝난 뒤 다시 실행할 수 있습니다.

내용을 다시 읽는 검증 과정 때문에 새로 복사하는 파일은 이전보다 시간이 더 걸릴 수 있습니다. 클라우드 API 업로드에는 사용자 PC에 파일 하나 크기만큼의 임시 여유 공간이 필요합니다. 검증 실패나 중단 후 클라우드의 `.safesync-staging`에 남은 미완료 파일은 정상 백업에 포함하지 않으며, 정상 파일과 혼동하지 않도록 별도로 보관합니다.

원자적인 파일 교체를 지원하지 않는 NAS나 가상 드라이브에서는 기존 파일을 유지하고 교체 오류를 알립니다. 해당 저장장치에서 먼저 시험하는 것이 좋습니다. 체크섬 검증은 전송 과정의 손상을 찾아내지만, 백업 완료 후 저장장치 고장이나 전원 손실로 발생하는 모든 손상을 보장하지는 않습니다. 실행 중인 데이터베이스의 여러 파일 간 일관성을 만드는 스냅샷 기능도 제공하지 않습니다.

## SafeSync 휴지통

교체되는 이전 파일과 원본에서 사라진 파일은 백업 위치의 숨김용 폴더인 `.safesync-trash`로 이동합니다. 로컬 폴더, 외장 드라이브, NAS/네트워크 드라이브 또는 데스크톱 동기화 폴더의 기존 백업 파일이 밖에서 삭제된 경우에도 이를 감지합니다. 원본 파일이 남아 있으면 해당 내용을 SafeSync 휴지통에 보존한 뒤 정상 백업 위치에 다시 복구합니다. 직접 연결한 Dropbox 및 Google Drive API 백업경로는 이 로컬 삭제 감시 대상에서 제외됩니다.

기본 창에서 로컬·외장·네트워크·Dropbox API·Google Drive API 백업 작업을 선택하고 **휴지통 관리**를 누르면 별도의 SafeSync 휴지통 창이 즉시 열립니다. 최근에 만든 휴지통 목록은 작업별 캐시에서 먼저 표시하고, 오래된 목록만 별도 작업에서 백그라운드로 갱신합니다. Google Drive는 저장된 변경 토큰으로 새로 생기거나 삭제된 항목만 확인하며, 로컬·클라우드 모두 목록을 읽는 동안 창을 이동·최소화·닫을 수 있습니다. 폴더 구조를 펼칠 필요 없이 모든 파일을 한 목록에서 볼 수 있으며 파일 이름, 삭제된 날짜와 시간, 지워지기 전 백업 경로와 크기를 표시합니다. Ctrl 또는 Shift 키를 사용하거나 **모두 선택**을 눌러 여러 파일을 선택한 뒤 한 번에 복구하거나 **선택 파일 완전 삭제**로 삭제할 수 있습니다. 로컬 파일과 Google Drive 파일은 영구 삭제되며 SafeSync에서 되돌릴 수 없습니다. 개인용 Dropbox API는 서버의 복구 기록을 영구 삭제할 수 없으므로 SafeSync 휴지통에서는 사라져도 Dropbox의 보존 기간 동안 웹사이트에서 복구될 수 있습니다. 클라우드 휴지통도 SafeSync 창에서 API를 통해 직접 읽고 관리합니다.

복구 위치에 파일이 이미 있으면 기존 파일을 삭제하지 않고 새로운 SafeSync 휴지통 항목으로 보관한 뒤 선택한 버전을 복구합니다. 같은 원래 경로의 여러 버전은 동시에 복구할 수 없으므로 한 버전만 선택해야 합니다. 복구를 시작하면 해당 백업 작업은 자동으로 일시정지되며 복구 후에도 일시정지 상태를 유지합니다. 복구된 파일과 원본을 확인한 다음 기본 창의 **다시 시작** 버튼으로 직접 재개하세요.

백업 위치에서 삭제된 파일을 보존하려면 해당 작업이 최소 한 번 정상 완료되어 백업 기록이 만들어져 있어야 하며, 삭제 시점에 원본 파일에 접근할 수 있어야 합니다. 기본 보관 기간은 100일이며 앱에서 바꿀 수 있습니다. 보관 기간이 지난 파일은 각 백업이 끝날 때 정리됩니다.

원본에서 삭제된 파일을 백업에서도 정리하고 싶지 않으면 해당 작업의 **원본에서 사라진 파일은 … 휴지통으로 이동** 옵션을 끄세요.

## 네트워크 드라이브

드라이브 문자(`Z:\백업`)와 UNC 경로(`\\서버\공유\백업`)를 모두 입력할 수 있습니다. Windows에 로그인한 사용자에게 해당 위치의 읽기/쓰기 권한이 있어야 합니다. 네트워크가 잠시 끊기면 그 작업은 실패로 기록되며 다음 파일 변화나 예약 시각에 다시 실행됩니다.

Google Drive는 5MB 이하 파일의 내용과 이름을 한 번의 요청으로 전송하고, 작은 파일은 최대 2개까지 동시에 임시 위치로 업로드합니다. 다음 파일의 안전한 사본 준비·전송과 현재 파일의 검증·교체를 겹쳐 진행하되, 기존 백업 교체와 충돌 처리는 순서대로 확인합니다. 큰 파일은 내용 체크섬별로 업로드 세션을 저장하므로 네트워크 단절·일시정지·재부팅 뒤에도 Google Drive가 확인한 전송 위치부터 이어 보냅니다. 세션이 만료되거나 원본 내용이 바뀌면 새 전송으로 시작합니다. 백업 진행 기록은 처리한 파일의 변경분만 작게 저장하고 주기적으로 전체 스냅샷에 합쳐 저장 비용을 줄입니다. 재시작할 때 이 기록을 읽어 완료 파일과 재시도 파일을 구분합니다.

다른 프로그램이 파일을 독점 사용하여 읽을 수 없으면 SafeSync는 그 파일만 **사용 중 대기**로 기록하고 나머지 파일의 백업을 계속합니다. 대기 파일은 동기화 상태 창에서 확인할 수 있으며, 30초부터 최대 5분까지 간격을 조절하며 해당 파일만 자동으로 다시 시도합니다. 프로그램을 재시작해도 대기 상태와 재시도 횟수는 유지됩니다. 잠긴 파일은 일반 오류 팝업으로 알리지 않으며, 메인 창이 숨겨졌거나 최소화된 동안 문제 알림은 소리를 내는 창 대신 알림영역 아이콘과 확인할 메시지 표시로 남습니다.

## Dropbox와 Google Drive API — 개인용 설정

SafeSync는 데스크톱 동기화 폴더 방식과 API 직접 연결 방식을 모두 지원합니다. API 방식은 **클라우드 계정**에서 계정을 연결한 뒤 작업의 **백업 방식**을 Dropbox API 또는 Google Drive API로 선택합니다. 클라우드 폴더 선택 창에서는 계정 안의 임의 폴더로 이동해 현재 폴더를 백업 대상으로 지정할 수 있습니다.

인증 토큰과 Google Client Secret은 Windows 사용자 보호 기능으로 암호화됩니다. 해당 보호 기능을 사용할 수 없는 특수 실행 환경에서는 `%LOCALAPPDATA%\SafeSync\secrets.key`의 사용자 전용 암호화 키를 사용합니다. 이 파일을 다른 PC로 복사하거나 삭제하면 저장된 인증 정보를 읽지 못할 수 있습니다.

### Dropbox API 준비

1. [Dropbox App Console](https://www.dropbox.com/developers/apps)에서 **Create app**을 선택합니다.
2. **Scoped access**와 **Full Dropbox**를 선택하고 개인용 앱을 만듭니다.
3. Permissions에서 `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read`, `files.content.write`를 활성화합니다.
4. OAuth 2 Redirect URIs에 `http://127.0.0.1:53682/`를 정확히 등록합니다.
5. App key를 SafeSync의 **클라우드 계정** 화면에 입력하고 **Dropbox 연결**을 누릅니다.

Dropbox 앱 권한을 나중에 바꾸면 SafeSync에서 연결을 해제한 뒤 다시 연결해야 새 권한이 적용됩니다.

### Google Drive API 준비

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들고 **Google Drive API**를 활성화합니다.
2. OAuth 동의 화면을 구성하고 본인의 Google 계정을 테스트 사용자로 추가합니다.
3. OAuth 클라이언트에서 애플리케이션 유형을 **데스크톱 앱**으로 선택합니다.
4. 발급된 Client ID와 Client Secret을 SafeSync의 **클라우드 계정** 화면에 입력합니다.
5. **Google Drive 연결**을 눌러 브라우저에서 전체 Drive 접근을 허용합니다.

Google OAuth 앱을 외부 사용자용 **테스트** 상태로 계속 두면 Drive 권한의 Refresh Token이 제한된 기간 뒤 만료될 수 있습니다. 본인만 사용하는 앱이라도 장기 자동 실행이 필요하면 Google Cloud의 OAuth 게시 상태와 경고 내용을 확인하세요.

### API 백업 동작

- Dropbox와 Google Drive에서 선택한 폴더 아래만 SafeSync가 백업 대상으로 사용합니다.
- Dropbox는 대용량 파일에 Upload Session을 사용합니다.
- Google Drive는 재개 가능한 업로드 세션을 사용합니다.
- 원격 파일의 ID, 수정 시간, 크기 및 서비스가 제공하는 해시·리비전 정보를 사용하며, 새 업로드는 서버 체크섬 검증까지 통과해야 완료로 처리합니다.
- 삭제되거나 교체되는 원격 파일은 선택 폴더 안의 `.safesync-trash`로 이동합니다.
- 100일이 지난 휴지통 묶음은 다음 백업 실행 때 영구 삭제됩니다.
- 네트워크 오류나 OAuth 취소는 해당 작업의 오류로 기록되며 다른 백업 작업은 계속됩니다.

API 직접 연결은 업로드와 서버 체크섬 확인 및 정상 위치 반영이 끝난 시점을 완료로 판단하므로 별도의 데스크톱 동기화 앱이 필요하지 않습니다.

## 데스크톱 동기화 폴더 방식

SafeSync는 공식 Dropbox 또는 Google Drive 데스크톱 앱이 만드는 동기화 폴더도 백업 위치로 사용할 수 있습니다. 작업의 백업 방식을 **로컬 / 네트워크 / 동기화 폴더**로 두고 **위치 선택**에서 해당 폴더를 지정하세요.

이 방식은 계정 비밀번호나 OAuth 토큰을 SafeSync가 보관하지 않고, 각 서비스의 공식 데스크톱 앱이 업로드 재시도와 오프라인 대기열을 담당한다는 장점이 있습니다. 파일은 먼저 로컬 동기화 폴더에 안전하게 기록된 뒤 클라우드로 올라갑니다. Google Drive의 스트리밍 드라이브도 Windows 폴더로 보이는 경우 지정할 수 있습니다.

SafeSync의 완료 표시는 동기화 폴더까지 로컬 복사가 끝났다는 뜻입니다. 실제 클라우드 업로드 완료 여부는 Dropbox 또는 Google Drive 알림 영역 아이콘에서 확인해야 합니다. 대량 백업은 Google Drive의 **파일 미러링** 또는 Dropbox의 **오프라인 사용 가능** 폴더를 권장합니다.

관련 공식 문서:

- [Dropbox 데스크톱 앱 설치 및 동기화](https://help.dropbox.com/installs/download-dropbox)
- [Google Drive 데스크톱용 Drive의 스트리밍과 미러링](https://support.google.com/drive/answer/13401938?hl=ko)

## 데이터와 로그

설정, 실행 기록, 클라우드 전송용 임시 사본과 미완료 전송 복구 기록은 `%LOCALAPPDATA%\SafeSync`에 저장됩니다. 실제 백업 데이터와 SafeSync 휴지통은 사용자가 지정한 백업 위치에 있습니다. 미완료 교체의 복구 기록이 있는 동안 데이터 폴더나 `.safesync-txn-…` 파일을 직접 삭제하지 마세요.

설치본 업데이트는 앱과 진행 중인 백업을 종료한 뒤 새 설치 EXE를 실행하세요. ZIP 실행본은 ZIP의 모든 파일을 함께 교체하세요. `SafeSync.Integrity.ps1`과 `SafeSync.TrashWorker.ps1`도 앱과 같은 폴더에 있어야 합니다. 기존 설정과 백업 파일은 그대로 사용할 수 있습니다.

## 주의 사항

- 최초 사용 때 중요하지 않은 테스트 폴더로 동작을 확인하는 것을 권장합니다.
- SafeSync는 단방향 백업 프로그램입니다. 양방향 동기화 프로그램이 아닙니다.
- 실행 중인 데이터베이스나 가상 머신처럼 계속 쓰이는 대형 파일은 애플리케이션 자체 백업 기능으로 먼저 일관된 스냅샷을 만든 뒤 SafeSync로 복사하는 편이 안전합니다.
