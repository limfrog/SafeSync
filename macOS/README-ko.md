# SafeSync macOS 0.3.0 — 통합 검증 중

Windows SafeSync 1.0.0-preview.10을 기준으로 SwiftUI/AppKit과 Swift 백업 엔진으로 이식했습니다. Windows 소스는 수정하지 않았습니다. 기존 Windows 실행 아이콘에서 추출한 같은 그림을 Dock·Finder·메인 화면·메뉴 막대에서 사용합니다.

현재 코드는 빌드·로컬/모의 클라우드 검사를 수행 중인 후보 버전입니다. 실제 Google Drive/Dropbox 계정, NAS, 외장 디스크, Intel Mac의 검증이 모두 끝난 완성판으로 표시하지 않습니다.

## 사용

macOS 14 이상에서 `SafeSync.app`을 실행합니다. **＋ 새 작업**에서 원본, 백업 방식, 백업 위치와 실행 방식을 선택합니다. 폴더는 서로의 하위 폴더가 되지 않도록 지정합니다. 작업 목록의 로컬 경로를 더블클릭하면 Finder에서 열립니다.

- **지금 실행 / 모든 작업:** 밀린 변경 이벤트를 먼저 반영한 뒤 저장된 변경 대기열로 증분 백업합니다. 첫 실행·감시 실패·이벤트 기록 미완료·네트워크 위치·7일 경과 시에는 전체 검사로 전환합니다.
- **전체 검사:** 모든 원본과 백업을 다시 비교합니다.
- **파일 변경 시:** FSEvents의 변경 기록을 모아 백업합니다. 변경 대기열과 이벤트 커서를 디스크에 저장합니다. 감시 실패·이벤트 손실·네트워크 위치에서는 메타데이터 전체 검사로 전환하며, 마지막 전체 검사에서 7일이 지나도 전체 검사를 합니다.
- **매일 정해진 시간:** 앱 실행 중이며 Mac이 깨어 있을 때 실행합니다. 그날 놓친 예약은 같은 날 앱이 실행되면 한 번 처리합니다.
- **일시정지 / 다시 시작:** 상태를 저장하며, 중지한 동안의 파일 변경도 대기열에 쌓입니다. 예약 작업은 재개 후 다음 예약 또는 미완료 오류 재시도 시 실행합니다.
- 창을 닫아도 메뉴 막대에서 계속 실행합니다. 완전히 종료하려면 메뉴 막대의 **프로그램 종료**를 선택합니다.

네트워크 드라이브는 Finder에서 먼저 연결한 `/Volumes/...` 폴더를 선택합니다. 백업 폴더가 없어졌을 때 대신 로컬 폴더를 만들지 않습니다. 안전한 원자적 교체를 지원하지 않는 NAS/가상 드라이브에서는 기존 파일을 보존하고 오류를 표시합니다.

## 탭과 양방향 동기화

- **백업 작업:** 새 작업·작업 관리·지금 실행·일시정지·모든 작업을 제공합니다. 작업 관리에서 종료하면 자동 실행을 멈추고 직접 다시 시작할 때 새 실행으로 진행합니다. 실행 중 일시정지는 파일 경계에서 현재 실행을 유지합니다.
- **동기화 상태:** 앱 실행 중의 이력을 시작/종료/소요/결과와 함께 보관합니다. 진행 상세·충돌·사용 중·오류·문제 해결 하위 탭을 제공합니다. 최신 실행 따라가기를 끄면 선택한 과거 기록을 유지합니다.
- **휴지통:** 작업/백업·원본 휴지통 선택, 파일·경로 검색, 선택 수/용량, 복구와 완전 삭제를 제공합니다. 역방향 교체 전 원본은 원본 쪽 휴지통에 보존됩니다. 복구 후에는 작업을 일시정지합니다.
- 환경설정은 세 탭 공통 오른쪽 버튼으로 엽니다. 활동 기록과 이력 영역의 구분선을 드래그해 높이를 조정합니다.

작업 편집에서 **단방향 백업 → / 양방향 동기화 ↔**를 선택합니다. 양방향은 로컬/네트워크 폴더와 Google Drive/Dropbox를 지원하며, 수정 시간의 선후 대신 마지막으로 양쪽 내용이 같았던 기록을 사용합니다. 최초 실행은 한쪽에만 있는 파일과 폴더를 양쪽으로 합칩니다. 처음부터 양쪽 내용이 다르거나, 이후 양쪽 수정·삭제와 수정이 겹치면 충돌로 남깁니다. 정상 비교 이후 한쪽에서 삭제한 항목은 반대편 SafeSync 휴지통으로 이동합니다. 양방향 모드에서는 양쪽 삭제 반영이 기본 동작입니다.

두 루트의 식별 정보를 저장하며 전체 목록을 양쪽에서 확인하기 전에는 삭제하지 않습니다. 폴더 연결 변경·읽기 실패·링크·남은 하위 항목이 있는 폴더는 자동 삭제하지 않습니다. 파일 잠금 대기는 다른 파일을 막지 않습니다. Drive의 동일 내용 중복 사본은 그대로 건너뛰며 삭제 판단 기준으로 삼지 않습니다. 다른 내용의 중복 사본은 문제 해결에서 모든 ID와 내부 파일을 보존하며 이름만 정리할 수 있습니다. 이름을 바꾼 사본은 일반 파일이므로 다음 양방향 실행에서 원본에도 복사될 수 있습니다.

위치·계정·방향을 수정하면 확인 후 새 비교 기록을 만들고 일시정지로 저장합니다. 기존 파일·휴지통·과거 실행 기록을 보존하며, 새 위치를 확인한 뒤 직접 재개합니다.

## 작업 목록 백업·복원

Windows 1.9.11과 같은 **파일 → 작업 목록 내보내기 / 작업 목록 가져오기** 메뉴를 제공합니다(macOS의 언어 설정에 따라 파일 메뉴가 File로 표시될 수 있습니다).

내보내기를 선택하면 기본 이름이 `SafeSync-jobs-yyyyMMdd.safesync-jobs.json`인 저장 창이 열립니다. `SafeSyncJobList` 버전 1의 Windows와 같은 JSON 형식으로 작업 이름, 경로, 백업 방식, 예약 시간, 원본 삭제 반영 여부, 동기화 방향과 일시정지/종료 대기 상태를 저장합니다. 클라우드 인증 정보, 계정 연결 ID, 마지막 실행 기록, 파일 스냅샷과 실제 백업 파일은 포함하지 않습니다.

가져오기는 파일을 검증한 뒤 **가져올 작업 수와 현재 작업 수를 보여 주고 목록 교체를 확인**합니다. 취소하면 목록을 바꾸지 않습니다. 백업·복구·확인 작업 중에는 가져오기를 막고, 파일 선택·확인 중에도 자동 백업이 새로 시작되지 않도록 합니다. 교체 직전에 현재 목록을 `~/Library/Application Support/SafeSync/job-list-backups`에 자동 보관합니다. 이 보관 파일도 같은 가져오기 메뉴로 복원할 수 있습니다. 보관 또는 저장에 실패하면 현재 목록을 유지합니다.

작업 ID와 원본·백업 위치·서비스·클라우드 폴더가 모두 같은 작업만 기존 스냅샷을 재사용합니다. 새 작업이나 위치가 달라진 작업에는 새 ID를 부여하여 첫 실행에서 다시 확인합니다. 환경설정과 연결된 클라우드 계정은 교체하지 않습니다. 새로 가져온 클라우드 작업은 **계정 연결 필요**로 표시되며, 작업 수정에서 계정과 폴더를 직접 선택하면 새 기록으로 시작합니다.

파일은 최대 10 MB, 작업은 최대 1000개이며 중복 ID, 잘못된 필드·예약 시간·참/거짓 값과 겹치는 백업 경로를 거부합니다. UTF-8 BOM이 있는 Windows 파일도 읽습니다. 다만 Windows의 드라이브 문자/UNC 경로는 macOS 위치로 자동 변환할 수 없으므로 실제 Mac 경로로 수정해야 가져올 수 있습니다. 연결되지 않은 Mac 외장/NAS 경로는 가져올 수 있지만 실행 전에 연결과 위치를 확인해야 합니다.

## 클라우드 계정

환경설정의 **클라우드 계정 관리**에서 연결합니다. 인증은 시스템 브라우저의 OAuth PKCE(S256)로 진행하고, 토큰과 Google Client Secret은 macOS Keychain에 저장합니다. 앱의 JSON 설정에 인증 토큰을 저장하지 않습니다. Windows DPAPI 토큰은 복사하지 말고 새로 로그인하세요.

### Google Drive 먼저 연결

1. Google Cloud에서 Google Drive API를 활성화합니다.
2. OAuth 동의 화면과 본인 테스트 사용자를 구성합니다.
3. OAuth 클라이언트의 유형을 **데스크톱 앱**으로 만듭니다.
4. SafeSync 연결 화면에 계정 표시 이름, Client ID, Client Secret을 입력합니다. 채팅이나 GitHub에 Secret을 보내지 마세요.
5. **브라우저에서 계정 연결**을 누르고 본인이 로그인·접근 동의를 완료합니다.
6. 새 백업 작업에서 **Google Drive API**, 연결한 계정과 백업 폴더를 선택합니다.

Google 로그인 앱이 테스트 상태인 경우 장기 인증 토큰의 수명은 Google의 OAuth 게시 정책을 따릅니다. 인증이 만료되면 계정을 다시 연결해야 합니다.

### Dropbox 연결

일반 사용자는 기본 SafeSync 앱으로 연결하므로 App key를 입력하지 않아도 됩니다. 개인 앱을 쓰려면 개발자 설정에 App key를 입력합니다. 이 경우 Full Dropbox 유형의 Scoped Access 앱을 만들고 `account_info.read`, `files.metadata.read`, `files.metadata.write`, `files.content.read`, `files.content.write` 권한을 설정합니다. OAuth Redirect URI를 `http://127.0.0.1:53682/`로 등록한 뒤 SafeSync에 App key를 입력하고 연결합니다.

공식 Dropbox/Google Drive 앱의 동기화 폴더도 **로컬 / 네트워크 / 동기화 폴더** 방식으로 사용할 수 있습니다. 이 방식의 완료는 로컬 복사 완료이며, 서비스까지의 업로드 완료는 공식 동기화 앱에서 확인해야 합니다.

### 연결 검증

계정 목록의 **연결 검증**은 새로 만든 고유한 `SafeSync-test-UUID` 클라우드 폴더와 전용 로컬 시험 폴더에서만 실행합니다. 한글 경로, 업로드와 서버 체크섬, 변경 없는 파일 건너뛰기, 교체, 충돌, 휴지통과 복구를 검사합니다. 실제 사용자 백업 폴더를 대상으로 하지 않으며, 클라우드 검증 폴더는 결과 확인을 위해 남깁니다.

## 파일 판단과 보호

경로·크기·생성/수정 시간의 스냅샷을 사용하고 필요할 때 내용 해시를 비교합니다. 같은 내용은 건너뜁니다. 백업 파일이 더 최신이거나 수정 시각이 같으면서 내용이 다른 경우에는 충돌로 남기고 다른 파일은 계속 처리합니다. Dropbox와 Google의 시간 정밀도 차이도 보수적으로 처리합니다.

**동기화 상태 → 문제 해결**에서 원본/백업의 경로·크기·생성/수정 시각·파일 식별 정보를 확인하고 **원본 → 백업**, **백업 → 원본**, **이름 변경 · 둘 다 보관**, **이번 동기화에서 제외**, **중복 이름만 정리**를 지정합니다. 여러 파일에 선택한 처리를 모아 확인 후 적용하며, 전체 선택을 먼저 재검증한 뒤 각 파일의 반영 직전에도 확인합니다. 바뀐 파일이나 계정·위치는 덮어쓰지 않습니다. 이전 실행 이력은 읽기 전용이며 최신 완료 기록에서만 처리합니다. 제외 선택은 영구 제외 규칙이 아닙니다.

- 로컬: 같은 볼륨의 임시 사본 작성 → SHA-256 검증 → 원본 변경 여부 확인 → `RENAME_SWAP` 원자적 교체 → 이전 버전 휴지통 보존 → 완료 확인.
- Dropbox: 임시 업로드 → Dropbox content hash 검증 → 기존 파일 리비전 재확인 → 복구 기록 저장 → 이전 파일 보존 → 검증된 새 ID 배치.
- Google Drive: 5 MiB 이하 파일의 단일 multipart 요청 / 큰 파일의 재개 가능한 업로드 → 서버 SHA-256 또는 MD5 검증 → 기존 버전 재확인 → 복구 기록 저장 → 검증된 새 ID 배치 → 이전 ID 휴지통 보존.
- 전송·교체 중 실패하면 복구 기록과 이전 사본을 남깁니다. 다음 실행은 복구부터 시작합니다. 원격 파일이 업로드 중 바뀌면 보존하고 재검사를 요청합니다.
- 파일 오류는 다른 파일의 백업을 막지 않습니다. 실패 파일은 저장된 변경 대기열로 30초부터 최대 5분까지 간격을 늘려 재시도합니다. 일시정지된 작업은 자동 재시도하지 않습니다.

Dropbox는 변경 커서를, Google Drive는 변경 토큰과 원격 항목 캐시를 저장합니다. 유효하지 않은 커서는 전체 목록 확인으로 전환합니다. Google의 5 MiB 이하 파일은 최대 2개까지 동시에 임시 업로드하며, 폴더 생성·서버 검증·복구 기록 저장·최종 교체는 순차 처리합니다. 같은 내용이라도 경로별 임시 사본과 업로드 키를 구분합니다. 큰 파일의 Google 업로드 세션은 내용 체크섬과 함께 저장하며 서버가 받은 위치를 확인하고 이어 보냅니다. Dropbox의 큰 파일은 업로드 세션으로 나누어 전송합니다.

## 사용 중인 파일 대기

동기화 상태 탭의 **사용 중** 표에서 작업·파일·최초 대기·최근 시도·시도 횟수·다음 시도를 확인합니다. **지금 다시 시도**는 실행 가능한 대기 작업을 즉시 재시도하며, 일시정지한 작업은 재개해야 합니다. 기록은 앱 재실행 후에도 남습니다. 대기 중에도 다른 파일은 계속 백업하며, 자동 재시도는 파일별 30초부터 최대 5분까지 간격을 늘립니다.

macOS에서 감지 가능한 사용 중 오류와 원본 변경을 분류하며, 공유 읽기 잠금으로 협조하는 프로그램의 배타적 파일 잠금을 확인합니다. macOS의 파일 잠금은 advisory 방식이므로 단순히 다른 앱에서 열었다는 이유만으로 잠긴 것으로 판단하지 않습니다. 복사 전후 정보와 해시 검증도 계속 수행합니다. 권한 오류·체크섬 오류는 일반 오류로 표시합니다.

## 클라우드 폴더 만들기

작업 설정에서 Google Drive 계정과 백업 위치를 고르면 폴더 선택 창이 열립니다. **새 폴더**를 누르고 이름을 입력한 뒤 **만들기**를 누르세요. 현재 표시된 위치 아래에 폴더를 만들고 생성된 폴더 안으로 이동합니다. **현재 폴더 선택**을 누르면 작업의 백업 위치에 반영됩니다. Dropbox 폴더 선택에서도 같은 버튼을 사용할 수 있습니다.

같은 이름의 파일·폴더가 있으면 다른 이름을 입력해야 합니다. 빈 이름, 경로 구분자, 제어 문자, `.safesync-`로 시작하는 내부용 이름은 사용할 수 없습니다. 생성 중에는 중복 클릭과 이동을 막습니다. 통신 오류가 발생하면 취소 후 **새로고침**으로 생성 여부를 확인하세요. 선택을 취소해도 이미 만든 클라우드 폴더는 남습니다.

## SafeSync 휴지통

교체된 이전 파일과, 이전에 백업했으나 원본에서 없어진 파일을 보관합니다. 로컬 백업 파일이 외부에서 삭제된 경우에는 원본 사본을 휴지통에도 보존한 뒤 백업을 다시 만듭니다. 원본 삭제를 반영하고 싶지 않으면 작업의 휴지통 이동 옵션을 끄세요.

**휴지통 관리**에서 여러 파일을 선택해 복구하거나 완전 삭제할 수 있습니다. 같은 경로는 한 번에 한 버전만 복구합니다. 복구 위치의 기존 파일도 먼저 휴지통에 보관합니다. 복구하면 해당 작업은 일시정지되며, 파일을 확인한 뒤 직접 재개합니다.

보관기간은 환경설정에서 1~3650일로 정하며 기본값은 100일입니다. 문제가 없는 백업이 완료된 후 만료 항목을 정리합니다. 미완료 교체 기록의 복구가 먼저 끝나야 자동 정리를 진행합니다. Dropbox는 개인용 API의 특성상 SafeSync에서 삭제한 뒤에도 Dropbox 웹 복구 기록이 서비스의 보존기간 동안 남을 수 있습니다.

## 환경설정과 알림

환경설정은 Windows와 같은 **보호 설정 / 화면 모드** 영역으로 구성합니다. 보호 설정에서 로그인 자동 시작, 휴지통 보관기간과 창 닫기·완료·오류 알림음을 관리하고, 화면 모드에서 라이트·다크·시스템 설정을 선택합니다. **설정 저장**을 눌러 적용하며 **닫기**는 수정 중인 값을 저장하지 않습니다. 보관기간은 1~3650일 범위의 정수여야 합니다. 완료 알림음은 기본 꺼짐이며, 메인 창이 표시된 상태의 정상 완료 때 재생합니다. 변경 없는 자동 확인마다 소리가 반복되지 않도록 자동 실행은 실제 복사·휴지통 이동이 있을 때만 재생합니다. 로그인 시 자동 시작은 macOS의 ServiceManagement를 사용하며 시스템 설정에서 승인이 필요할 수 있습니다. 실제로 설치한 앱에서 사용자 선택으로 켜세요.

앱 메뉴 **SafeSync → About SafeSync**에서 원본 아이콘, 앱 버전·빌드 번호, 제작자와 이메일, GitHub 링크를 확인합니다. 버전은 배포 앱의 Info.plist 값을 사용하며 환경설정에서는 표시하지 않습니다. 화면 모드는 메인의 세 탭·환경설정·About에 함께 적용합니다.

진행·휴지통은 메인 창의 탭으로 열립니다. 메인 창을 닫거나 최소화해도 백업은 계속하며 메뉴 막대에서 다시 열 수 있습니다. 숨겨져 있을 때 오류 창을 갑자기 띄우지 않고 메뉴 막대 경고와 저장된 확인 메시지로 남깁니다. 같은 파일의 같은 문제는 중복 메시지를 만들지 않습니다.

## 데이터 위치

`~/Library/Application Support/SafeSync`에 설정, 파일 스냅샷, 변경 대기열, 오류와 전송 복구 기록을 보관합니다. 실제 백업과 휴지통은 선택한 로컬/클라우드 폴더에 있습니다. Google 업로드 재개 주소가 담긴 세션 파일은 사용자 전용 권한으로 저장합니다. 복구 기록과 `.safesync-staging` 파일은 임의로 삭제하지 마세요.

서로 다른 원본을 같은 백업 트리에 겹쳐 등록하지 못하게 제한합니다. 작업 위치·계정·방향을 바꾸면 확인 후 새 비교 기록과 일시정지 상태로 저장합니다. 손상된 설정이나 스냅샷은 조용히 초기화하지 않고 자동 실행을 멈춥니다.

## 빌드와 검증

Swift 6 도구체인과 macOS SDK가 필요하며 외부 Swift 패키지 의존성은 없습니다. 아이콘 빌드에는 Command Line Tools의 Python 3와 sips를 사용합니다.

```sh
cd macOS
scripts/check.sh
scripts/build-app.sh
ARCHITECTURE=universal scripts/build-app.sh
```

`build/SafeSync.app`이 만들어집니다. `APP_OUTPUT`으로 별도 출력 경로를, `SIGNING_IDENTITY`로 Developer ID 서명 신원을 지정할 수 있습니다. 지정하지 않으면 개인용 ad-hoc 서명입니다. 일반 공개 배포를 위한 Developer ID 서명과 Apple 공증은 별도로 완료해야 합니다.

Command Line Tools만 있는 환경에서는 `scripts/check.sh`로 실제 파일시스템과 메모리 클라우드 통합 검사를 실행합니다. XCTest 프레임워크가 있는 전체 Xcode 환경에서는 `swift test`로 초기 로컬 회귀 검사도 실행할 수 있습니다. 클라우드 모의 검사는 실제 서비스 API의 호환성·계정 권한 검증을 대신하지 않습니다.

## 검증 범위와 남은 배포 확인

로컬 APFS 파일 작업, 메모리 기반 Dropbox/Google 저장소의 교체·충돌·중단 복구, 변경 대기열과 보관기간, PKCE 매개변수를 자동 검사합니다. 실제 계정 로그인을 마친 뒤 Google Drive와 Dropbox의 연결 검증을 각각 수행해야 합니다. NAS·외장 드라이브 분리·잠자기·Intel 실제 실행·다른 macOS 버전·장시간 대용량 전송도 별도 확인 대상입니다.

실행 중 데이터베이스/가상 머신의 다중 파일 일관성 스냅샷, 디스크 이미지 수준의 ACL/확장 속성 보존을 보장하는 도구는 아닙니다. 심볼릭 링크는 따라가지 않습니다. 자기 백업으로 변경이 반복되지 않도록 SafeSync 자신의 런타임 데이터 폴더는 원본 검사에서 제외합니다. macOS의 공유 읽기 잠금은 Windows의 쓰기 제한 잠금과 동작이 다르며 복사 전후 메타데이터와 해시 검사도 함께 사용합니다. 로컬 작업 동시 실행, Google 메타데이터 100개 일괄 요청, 휴지통 캐시 등은 Windows 구현과 차이가 남아 있습니다.
