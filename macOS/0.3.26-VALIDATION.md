# macOS 0.3.26(35) Google Drive 수정 시각 보존

## 원인과 수정

macOS GoogleDriveStorage.move는 이름/부모 변경 시 modifiedTime을 생략했다. 서버가 게시 시각으로 변경하면 이후 원본이 더 오래된 것으로 판단된다. Windows는 이미 modifiedTime을 보존하므로 수정·재빌드하지 않는다.

- 파일 이동/동일 폴더 이름 변경/휴지통 보관·복원에서 전달받은 수정 시각을 millisecond RFC3339로 보존한다. 폴더는 기존 요청을 유지한다.
- 기존 오류 사본의 자동 처리는 Google 단방향에서만, 성공 검증 버전1·원격 전체 메타데이터(특히 ID/버전/해시)·검증 사본 정보가 정확히 같고 원본이 마지막 성공 시각 이후 수정된 경우에 한한다. 기존 사본 보관/교체 직전 재확인/체크섬은 유지한다.
- 기록 없음·원격 정보 변경·원본 시각 역행은 기존 충돌 보호를 유지한다. 과거 파일 날짜를 일괄 변경하거나 충돌을 무조건 덮어쓰지 않는다.

## 검사

- 실제 GoogleDriveStorage PATCH를 가로채 modifiedTime 생략 시 서버 시각으로 바뀌는 응답을 재현하는 XCTest 추가. 이동/이름 변경/보관 경로 모두 원본 시각 확인.
- 성공 기록에 잘못된 게시 시각이 저장된 합성 클라우드에서 재시작 후 수정 파일 백업/이전 사본 보관/동일 파일 건너뛰기, 원격 변경/기록 없음/원본 시각 역행 차단 검사 추가.
- GitHub macOS [40658376659](https://github.com/limfrog/SafeSync/actions/runs/40658376659), 소스 d81c4bc: 전체 핵심 시나리오 및 신규 4개 보호 시나리오, XCTest 30개, 실제 Store 합성 네트워크·예약 24개 통과. Universal arm64/x86_64, 번들 서명(ad-hoc)·ZIP 검증 통과.
- 배포 ZIP의 0.3.26(35) 버전, OAuth 등록 리소스 존재, 개발용 데이터 주입/시험 실행 파일 부재 확인.
- 사용자 맥/실제 계정은 접속하지 않음. 실계정 연결 검증 성공까지 확인했다는 뜻은 아님.
