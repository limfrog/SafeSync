# macOS 이식 검증 현황 — 2026-10-20

Windows 기준: **1.0.0-preview.10 (`54452ef`)**. macOS 후보: **0.3.7 (16)**.

## 0.3.7 Dropbox 금지 이름과 반복 복구 실패

- 진단한 미완료 게시 대상이 `.DS_Store`임을 확인. 읽기 전용 API로 인증·루트·임시 업로드 정상 확인. 별도 시험 파일에서 `409 / to/disallowed_name` 재현.
- Dropbox 예약 OS 메타데이터 3종을 전송/양방향 판단에서 제외. 제외를 삭제로 해석하지 않으며 다른 숨김 파일·Google/로컬은 유지.
- 해당 미완료 게시 기록은 `cloud/excluded-transactions`에 보관하고 원격 사본은 유지해 다음 백업을 차단하지 않음.
- 409 오류를 안전한 태그로 구분해 안내. metadata는 실제 not_found만 nil, 커서는 reset만 전체 재조회로 처리.
- 자동 시나리오 67개 통과(기존 63 + 회귀 4). 실서비스에서 정상 시험 업로드/이동·금지 이름 오류 재현, 원본/임시/기록 보존 회귀 검증. 사용자 전체 백업은 수정 앱으로 재실행하지 않음.
- 별도 실서비스 시험 폴더의 파일은 보존. 기존 백업/설정/인증은 변경하지 않음.

## 0.3.6 확인할 메시지 창

- 헤더 버튼의 충돌 탭 이동을 전용 메시지 창 열기로 변경. 0개 빈 상태도 표시.

- 별도 임시 데이터 QA 앱에서 실제 버튼으로 빈 창/메시지 목록 열기, 닫기, 전체 상세, 재열기·상태 유지, 충돌/오류 탭 이동 7개 확인 통과. 사용자 데이터/클라우드 전송은 검증에 사용하지 않음.
- universal 앱 빌드·코드서명·ZIP 검증 완료.

## 남은 실제 검증과 차이

- 실제 Google Drive/Dropbox의 양방향 전송과 신규 Dropbox 기본 앱 로그인은 아직 통과로 표시하지 않음. 클라우드 검사는 메모리 제공자와 모의 HTTP 어댑터 검사이며 실서비스 검증을 대신하지 않음.
- 네이티브 화면 도구가 환경설정 창을 여는 단계에서 다시 종료되어, 설정/새 계정 탭의 실제 표시·로그인과 설정 저장/취소는 이번 화면 검사에서 완료하지 못함. 메인·탭·비교·복구는 위와 같이 확인.
- NAS·외장 디스크 분리·잠자기·대용량 장시간 전송, Intel 실기기와 다른 macOS 버전은 별도 검증 필요.
- 양방향 엔진은 양쪽 전체 목록·체크섬을 보수적으로 재확인한다. Windows USN/메타데이터 일괄 조회 최적화와 동일한 성능이라고 보장하지 않음. macOS 파일 잠금은 advisory 방식.
- 실행 이력은 앱 종료 시 사라짐(Windows와 동일). 영속 백업 기록·문제·재시도·변경 대기열은 계속 저장함.
- Developer ID 서명·Apple 공증·자동 업데이트/설치 도구는 별도. 이번 빌드는 ad-hoc 서명.

## 0.2.2 작업 목록 내보내기·가져오기

Windows 릴리스 `01e4beb`의 메뉴명·대화창·v1 JSON 허용 필드를 기준으로 구현했습니다. 기존 목록 자동 보관, 실행 중 가져오기 차단, 동일 ID·위치에서만 스냅샷 재사용, 저장 실패 시 기존 목록 보존을 포함합니다. 인증 정보는 문서에 포함하지 않으며 새 클라우드 작업은 사용자가 계정을 다시 지정합니다.

기존 24개 검사에 문서 왕복·BOM/빈 목록·스냅샷 재사용·형식/한도 거부·필드 검증·다른 OS 경로·자동 보관·저장 실패 보존 시나리오 8개를 추가했습니다.

## 0.2.3 우선 보완

- 사용 중/변경 중 파일을 일반 오류와 분리하고, 최초 대기·최근 시도·횟수·다음 시도와 즉시 재시도 버튼을 추가했습니다. 파일별 대기 기록을 저장하고 자동 재시도는 30초~5분으로 조절합니다. macOS advisory 공유 잠금과 변경 검사를 사용하며 Windows의 강제 쓰기 제한과 같다고 표시하지 않습니다.
- 수동 백업의 강제 전체 검사 조건을 제거했습니다. 메인 콜백 큐를 막지 않고 FSEvents를 flush한 뒤 변경 대기열의 체크포인트를 잡습니다. 기록 미완료·감시 실패·네트워크·7일 경과·명시적 전체 검사는 보수적으로 전체 검사합니다. 증분 실행에서 처리하지 않은 기존 충돌과 대기 기록도 보존합니다.
- Google Drive 5 MiB 이하 multipart 단일 요청과 최대 2개 임시 업로드를 추가했습니다. 폴더 생성과 검증/배치/이전 버전 보존은 순서대로 진행합니다. 경로별 임시 사본을 분리하고 실패·취소 시 이전 파일과 복구 기록을 보존합니다. 큰 파일의 재개 가능한 전송은 유지합니다.
- 완료 알림음 설정(기본 꺼짐)을 추가했습니다. 오류/대기 상태와 변경 없는 자동 확인에서는 완료음을 울리지 않습니다.
- 기존 32개와 보완 12개, 총 44개 검사가 통과했습니다. 보완 검사는 실제 파일 잠금/해제, 기존 사본 보존, 대기 기록/이전 JSON 호환, 증분 정책, Google 어댑터의 요청 구성(모의 HTTP), 2개 업로드 상한/동일 내용 파일 분리/실패 격리/취소 후 재시작/삭제된 경로의 오래된 문제 정리을 다룹니다.
- 검사 셸에서 FSEvents 서비스가 시작되지 않아 해당 시나리오는 감시 실패 시 전체 검사 전환을 검증했습니다. 실제 이벤트 전달과 수동 실행 직전 flush는 이 검사에서 통과한 것으로 표시하지 않습니다. 실제 Google/Dropbox API 검증과 NAS·잠자기 검증도 여전히 별도입니다.
- 남은 Windows 차이: 로컬 작업 병렬 실행, Google 메타데이터 일괄 요청, 휴지통 캐시, 기존 작업 경로 변경, 설치/업데이트 도구와 배포 공증.

### 0.2.3 네이티브 화면 확인

실행 앱의 설정에서 0.2.3과 완료 알림음 기본 꺼짐을 확인했습니다. `/private/tmp`의 전용 임시 작업으로 사용 중 대기 표·즉시 재시도 버튼·최초/최근/다음 시도·횟수를 확인했습니다. 잠긴 파일이 대기하는 동안 다른 파일의 복사를 확인했고, 편집기처럼 원본을 새 inode로 저장한 후 재시도하여 대기 0건과 복사 결과를 확인했습니다. 추가 파일의 수동 백업 후 파일 내용과 `lastFullScan`이 바뀌지 않은 것을 확인하여 네이티브 앱의 증분 경로도 확인했습니다. 검사 작업은 목록에서 제거했습니다. 완료 알림음의 실제 스피커 출력과 장시간 이벤트 경계/잠자기 검증은 별도입니다.

## 0.2.4 클라우드 폴더 생성

Google Drive/Dropbox 폴더 선택 창에 새 폴더와 새로고침 버튼을 추가했습니다. 현재 폴더를 부모로 생성하고 성공한 폴더 ID로 이동한 뒤 사용자가 현재 폴더 선택으로 확정합니다. 생성 중에는 중복 클릭·이동·시트 닫기를 막습니다. 이름 검증, 숨겨진 일반 파일을 포함한 중복 검사, 오류 표시와 새로고침을 지원합니다. 통신 오류 때는 생성 요청을 자동 반복하지 않습니다.

기존 44개에 폴더 생성 검사 4개를 추가하여 총 48개 자동 검사를 통과했습니다. 양 서비스의 부모/하위 폴더·한글 이름·중복, 잘못된 이름·파일 충돌, Google 어댑터의 폴더 MIME/부모 ID POST 요청(모의 HTTP), 생성 실패 전달을 확인했습니다. 실제 Google 계정의 폴더 생성 검증을 대신하지 않습니다.

네이티브 0.2.4 앱에서 기존 연결 계정의 실제 Google Drive 폴더 목록을 조회했고, 새 폴더 버튼·생성 위치·이름 입력 창·빈 이름/경로 구분자 차단·정상 이름의 만들기 활성화·취소를 확인했습니다. 실제 폴더 생성 요청은 보내지 않았습니다. 앱은 폴더 선택 창에 두었습니다.

## 0.2.5 환경설정과 About

Windows 1.9.13의 환경설정을 참고해 제목/설명, 보호 설정, 화면 모드, 하단 닫기/설정 저장 배치로 변경했습니다. 체크박스 알림음과 숫자 보관기간 입력을 사용하며 기존 시스템 화면 모드 선택도 유지합니다. 저장 전에는 설정을 변경하지 않고 보관기간을 검증한 뒤 자동 시작 등록과 환경설정을 적용합니다. 닫기 버튼은 편집 값을 버립니다.

앱 메뉴의 About SafeSync에 원본 아이콘, 버전/빌드, 제작자, 이메일과 GitHub 링크를 모았습니다. 버전은 번들 메타데이터에서 읽습니다. 환경설정의 버전/제작자/이메일 행은 제거했습니다. 독립 진행·휴지통·About 창에도 저장된 화면 모드를 적용합니다.

Universal 빌드·ad-hoc 서명 검증과 기존 48개 자동 검사를 통과했습니다. 새 앱의 메인 창 실행과 0.2.5 표시는 확인했습니다. 이후 화면 검사 도구의 네이티브 연결이 종료되어 환경설정/정보 창의 시각 검사와 실제 저장/취소 동작 확인은 완료하지 못했습니다. 도구 재연결 후 확인할 항목으로 남깁니다.
