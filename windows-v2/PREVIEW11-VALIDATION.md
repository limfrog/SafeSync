# SafeSync 1.0.0-preview.11 안전성 수정 — 2026-10-20

## 수정 내용

1. 단방향 로컬·클라우드 엔진에서 ‘같은 크기 + 2초 이내 시각’을 내용 동일성으로 취급하던 분기를 제거했다. 비교 대상인 같은 크기 파일은 해시를 검증한다. 같은 내용은 건너뛰고, 다른 내용인데 시간 순서가 불확실하면 기존 백업과 충돌·재시도 상태를 보존한다. 클라우드 체크섬이 없는 항목도 시간만으로 완료 처리하지 않는다.
2. 단방향 원본과 로컬 백업 루트의 식별정보를 스냅샷에 보관하고 실행·개별 처리·삭제 경계에서 재확인한다. 루트 열기 실패는 가짜 생성 시각으로 대체하지 않는다. 파일 부재 확인은 Exists만 사용하지 않고 상위 경로의 접근 오류·연결 지점·파일/폴더 교체를 구분한다.
3. 원본 부재에 따른 오류가 발생해도 기존 파일 메타데이터와 삭제 확인 근거를 잃지 않는다. 해당 항목은 재시도 목록에 남는다. 연결 복구 후 다시 실행할 수 있다.
4. 클라우드 삭제 기록 재처리에도 같은 확인을 적용한다. 원격 메타데이터 조회 이후 실제 이동 직전에 검사하므로 그 사이 원본이 사라지거나 재등장하면 삭제하지 않는다.
5. 구버전 스냅샷의 파일은 최초 한 번 재검증한다. 기존 원본을 관찰한 근거가 없는 누락 파일은 자동 삭제하지 않는다. 최초 재검증과 수동 전체 비교는 종전 메타데이터 전용 검사보다 오래 걸릴 수 있다. 평상시 증분 대상 선정은 유지한다.

## 범위와 제한

- 설치본 제작·검증 과정에서 실제 실행 중인 SafeSync, 실제 작업·계정·스냅샷, 클라우드 및 NAS 파일을 변경하지 않았다. 이후 사용자 요청으로 검증된 동일 설치본·소스를 GitHub에 게시하고 홈페이지 개별 페이지를 갱신한다. 자동 설치는 하지 않으며 Apps 목록은 별도 공개 지시 전까지 숨긴다.
- 이번 원격 검사는 모의 저장소 검사다. 실제 NAS 단절·실제 클라우드 장애 주입·장기간 연속 운전·별도 깨끗한 PC 검사는 수행하지 않았다. UI 변경이 없어 이번에는 UI 자동 조작 검사를 다시 실행하지 않았다.
- 기존 배포의 코드 서명 부재, 전체 드라이브 OAuth 권한 범위, NAS 통신 암호화 미확인이라는 보안 한계는 이번 엔진 수정으로 해결되었다고 주장하지 않는다.
- 이미 과거에 누락되거나 삭제 반영된 자료를 자동 복구하는 업데이트는 아니다. 최초 재검증에서 나타나는 충돌·원본 확인 필요 항목은 사용자가 확인해야 한다.
- 원본 폴더를 의도적으로 다른 폴더로 교체한 경우 기존 폴더를 다시 연결하거나 자료 확인 후 새 작업으로 등록한다. 안전성 검사를 자동 무시하지 않는다.
