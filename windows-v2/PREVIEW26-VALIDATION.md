# 공개 프리뷰 26 / macOS 0.3.22(31)

## 변경 범위

- Windows Google Drive 초기 목록을 물리 파일 ID·상위 폴더 ID 그래프로 구성하고 저장합니다. 재시작 시 변경 페이지를 모두 반영한 뒤 경로를 재구성하므로 같은 상위 경로를 파일마다 HTTP로 다시 탐색하지 않습니다. 이전 형식은 한 번 새 그래프를 작성합니다.
- 최초/강제 조회는 폴더별 목록을 최대 100개씩 묶어 요청합니다. 재시작 증분 조회는 저장한 그래프와 커서를 재사용합니다. 폴더 이동·삭제·새로 들어온 하위 트리와 중복 이름을 반영하며, 만료된 커서만 재구성합니다.
- 권한 오류·응답 누락·취소·순환 경로는 기존 색인을 보존하고 중단합니다. 쓰기/삭제 전에는 기존의 루트·계정·폴더 경로·중복 검사와 안전 전송·교체 보호를 계속 사용합니다. 저장된 ID 자체가 쓰기 허가가 되지는 않습니다.
- 두 OS에서 상세 로그를 기본으로 끄고 환경설정에서 켜고 끌 수 있습니다. 문제 검증 때만 켜라는 안내와 툴팁을 제공합니다. 활동기록은 계속 표시합니다.
- macOS는 요청별 네트워크 단계·바이트 진행·정체·연결 재사용을 기록합니다. Windows는 네트워크 공개 이벤트·본문 진행과 로컬 사본 준비의 읽기/쓰기/해시/반영/잠금 대기를 분리합니다. 민감정보 제외와 순환 용량 제한을 유지합니다.
- 검증된 파일의 내용·ID·크기·시간이 같고 제공자 버전 정보만 바뀐 경우 불필요한 재검증을 줄입니다. macOS는 업로드 때 확인한 SHA-256을 보관해 나중에 Google이 SHA-256을 제공하는 경우에도 다시 전체 해시를 만들지 않습니다. 내용 해시가 달라지면 재검증합니다.

## 양방향 동기화 결정

| 위치 | 단방향 | 양방향 |
|---|---|---|
| 로컬·외장·NAS | 지원 | 지원 |
| Dropbox API | 지원 | 지원 |
| Google Drive API (`drive.file`) | 앱 관리 폴더 지원 | 제공하지 않음 |

`drive.file`은 선택 폴더 안에서 다른 앱이 만든 모든 파일을 자동으로 허용하지 않습니다. 양쪽을 완전히 같은 폴더로 유지하거나 조회되지 않는 파일을 삭제로 판단할 수 없으므로 Google API 양방향을 활성화하지 않습니다. UI에서 선택 항목을 숨기고 기존/수입 설정도 실행 전 차단합니다. 전체 Drive 권한을 다시 요청하지 않습니다. Google Drive 데스크톱 동기화 폴더를 로컬 경로로 선택한 경우에는 로컬 양방향 기능을 사용할 수 있습니다.

## 성능 검증과 한계

Windows 합성 Drive(200개 하위 폴더, 파일 1,000개)의 초기 목록은 외부 HTTP 요청 5회, 같은 그래프 재시작/파일 한 개 변경은 루트 확인+변경 목록 2회로 검사합니다. 배치 안의 내부 API 호출은 별개이며 Google 할당량도 적용됩니다. 이는 요청 수 검증으로 실제 네트워크 소요 시간의 배수를 보장하지 않습니다.

검사 결과와 최종 패키지 SHA-256은 최종 CI 완료 후 아래에 기록합니다. 사용자 실제 백업 데이터·계정·상세 로그는 공개하지 않습니다. 새 버전은 자동 업데이트 목록에도 등록하는 공개 프리뷰이며, 정식 안정판 또는 Google 공개 심사 완료를 뜻하지 않습니다. 기존 전체 Drive 권한 계정은 제한 권한으로 다시 연결하고 앱 관리 폴더의 새 작업을 만들어야 합니다. 이전 클라우드 데이터는 지우지 않습니다.
