# 작동 분석 로그 — Windows preview.25 / macOS 0.3.21(30)

성능 원인을 확인하기 위한 시험본입니다. 백업·충돌·삭제 정책과 Google Drive 제한 권한 방식은 유지합니다. 실행 중인 기존 앱에는 새 기록 기능이 소급 적용되지 않으며, 새 설치본으로 실행한 이후부터 기록됩니다.

## 기록 위치

- Windows: `%LOCALAPPDATA%\SafeSync2-Preview\logs\operations`
- macOS: `~/Library/Application Support/SafeSync/logs/operations` (실제 경로는 Storage.applicationDirectory 기준)
- `Diagnostic-*.jsonl`: 단계별 상세 기록
- `Summary-*.jsonl`: 초기 준비와 실행 결과를 별도로 보관하는 요약 기록

외부로 자동 전송하지 않습니다. 분석을 요청할 때는 이 폴더만 전달하면 되며, 계정 설정·스냅샷·전송 세션 파일은 필요하지 않습니다.

## 확인할 항목

- 앱 초기화와 설정 읽기, 스냅샷 및 증분 체크포인트 읽기
- 작업 잠금·계정 잠금 대기, 오프라인 변경 저널 읽기와 전체 비교 선택 이유
- 중단된 로컬/클라우드 교체 복구, 원본 폴더 스캔
- 인증 토큰 교환, 원격 목록 읽기·변경 목록 갱신·메타데이터 일괄 확인
- 처리 대상 구성 후 첫 파일 처리까지의 시간(`prepare.ready`), 첫 실제 업로드까지의 시간(`transfer.first`)
- 안정 전송 사본/해시 준비, 업로드·청크 요청, 서버 검증·이동·최종 확인
- 파일별 실패 유형·운영체제 오류 코드·재시도 대기, 작업 결과와 실행 총시간

요청 주소·파일 경로·파일 이름·계정 이름·인증 헤더·토큰·응답 본문·예외 메시지는 기록하지 않습니다. 같은 실행 세션 안에서 파일을 연관 지을 때는 임의 키로 만든 HMAC 식별자를 사용합니다. CPU/디스크/네트워크의 실제 사용률을 수집하는 시스템 추적기는 아닙니다.

## 용량과 분석 주의점

- 상세 파일은 각 8MiB, 최대 8개. 요약 파일은 각 8MiB, 최대 2개로 별도 순환합니다. 시작/순환 시 14일을 넘긴 기록을 정리합니다.
- 대기열은 8,192건으로 제한합니다. 밀리면 백업을 기다리게 하는 대신 기록 일부를 생략하고 `log.dropped`로 알립니다. 로그 저장 장애가 백업 결과를 실패로 바꾸지 않습니다.
- HTTP 시간은 Windows에서는 요청 시작부터 응답 헤더까지(전송 요청 본문 포함), macOS에서는 응답 본문을 받은 시점까지입니다. 두 OS의 값을 직접 동일 기준으로 비교하지 않습니다.
- HTTP `Bytes`는 요청 본문 길이이며 순수 파일 업로드량과 다릅니다. 재시도는 같은 바이트를 다시 포함할 수 있습니다. 배치 요청 1건은 여러 내부 API 요청을 포함합니다.
- 중첩·병렬 구간은 시간이 겹칩니다. 각 구간 합계를 전체 실행 시간으로 해석하면 안 됩니다. `reported_stage.wall`은 화면에 마지막으로 보고된 단계의 벽시계 시간입니다.
- `span.end`는 구간을 빠져나왔다는 뜻이며 성공 판정은 `file.handled`/`run.result` 및 오류 기록과 함께 확인합니다.
- 진행 도중 종료한 실행은 `run.end`가 없을 수 있습니다. 마지막 줄이 잘렸거나 상세 로그가 순환된 경우 일부 분석은 제한됩니다.

`windows-v2/scripts/analyze-operation-log.py`는 표준 Python만으로 폴더를 읽어 실행별 준비 시간·요청 횟수·요청 시간·상태 코드를 요약합니다. 외부 통신은 하지 않습니다.
