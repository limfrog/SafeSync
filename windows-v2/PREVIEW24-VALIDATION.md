# 프리뷰 24 — Google Drive 하위 폴더 반복 조회 개선

Windows 1.0.0-preview.24 / macOS 0.3.20(29), drive.file 별도 시험본.

## 구현

- 변경 피드를 반영한 기존 원격 카탈로그의 폴더 ID를 작업 인스턴스에 불러온다. 전송 중 확인·생성한 폴더도 같은 인스턴스에서 재사용한다. 계정·작업 루트 사이에 캐시를 공유하지 않는다.
- 저장된 ID만 믿고 읽거나 쓰지 않는다. Windows 일반 조회는 루트와 조상 폴더의 현재 이름·상위 ID·삭제 여부를 일괄 확인한 후 최종 폴더의 파일 목록을 새로 읽는다.
- 실제 변경에 사용하는 경로와 macOS 폴더 경로는 각 조상 폴더의 최신 이름 목록을 한 번의 batch 요청으로 확인한다. 새 중복 이름을 확인하며, 1,000개를 넘는 목록은 모든 페이지를 다시 받아 검사한다. 변경·불일치는 캐시에서 제거하고 정상 경로 탐색으로 돌아간다. 루트 접근 실패·권한 오류·불완전한 응답은 ‘파일 없음’으로 간주하지 않는다.
- 동시에 겹치는 폴더/자식 목록 조회만 공유한다. 완료·실패·취소 응답을 다음 작업의 최신 정보로 보관하지 않는다. 폴더 생성은 같은 상대 경로/상위 ID와 이름에 대해서만 순서대로 실행하며, 잠금 뒤 재조회와 생성 후 중복 검사를 거친다.
- 변경 피드 갱신·폴더 이동·삭제 시 관련 힌트를 비운다. 중복 경로와 그 하위 경로는 카탈로그에서 빠른 경로로 등록하지 않는다.
- 소형 파일 전송, 원본 변경 감지, 서버 체크섬, 게시 직전 확인, 이전 버전 보관과 중단 복구는 유지한다. macOS는 준비 후 임시/최종 부모 폴더가 바뀐 경우에도 게시를 보류한다.

## 비교 결과와 범위

- 합성 4단계 경로의 Windows 파일 확인: HTTP 왕복 6회 → 2회(조상 일괄 확인 1회 + 최신 파일 목록 1회). 겹치는 8개 확인도 같은 2회로 합쳐졌다.
- macOS의 기존 4단계 폴더 확인: 4회 → 1회. 겹치는 폴더 확인 8개와 파일 목록 확인 8개도 각각 1회로 합쳐졌다.
- batch 내부 개별 조회는 Google API 할당량에 각각 포함된다. 위 수치는 네트워크 왕복 감소이며 할당량이 사라지거나 전체 백업이 같은 배수로 빨라진다는 뜻이 아니다. 파일 바이트 전송·원본 읽기·해시·게시/복구 작업의 시간은 여전히 필요하다.
- 프리뷰 22·23의 연결·작업·완료 기록을 이어 사용한다. 재연결·새 백업 폴더·스냅샷 초기화는 필요하지 않다. Google Cloud 심사와 일반 업데이트 목록은 바꾸지 않는다.

## 검증

- 로컬 Windows 핵심 회귀 1,398개와 별도 프로토콜/성능 검사 91개 통과. 같은 이름의 신규 중복, 후속 페이지 중복, 이동·이름 변경, 403, 응답 누락, 취소 후 재시도, 중복 없는 동시 폴더 생성을 검사했다.
- 실제 제한 권한 Google 계정으로 새 시험 폴더에서 전송·서버 체크섬·동일 파일 건너뛰기·교체·휴지통·복구를 통과했다. 시험 폴더 자동 삭제 및 기존 설정 파일 SHA-256 불변을 확인했다. 기존 백업과 원본 파일은 변경하지 않았다.
- macOS 15 최종 CI: XCTest 20개(신규 폴더 검사 5개 포함), 기존 통합 검사와 실제 Store 모사 경로 24개 통과. Apple Silicon·Intel Universal 빌드, 번들 등록, 임시 코드 서명과 ZIP 검사를 통과했다.
- Windows Server 2022·2025 최종 CI: 실제 새 프로세스 재시작·격리 NTFS·SMB·단방향/양방향·오프라인 변경·강제 중단 복구와 핵심 1,398개 통과. 2022에서 라이트·다크 UI 623개, 설치/제거 34개, 설치 페이로드 해시 511개 및 설치 후 UI 623개를 통과한 패키지를 배포한다.
- 최종 Windows CI: https://github.com/limfrog/SafeSync/actions/runs/40370818849
- 최종 macOS CI: https://github.com/limfrog/SafeSync/actions/runs/40370818576
- 실행 코드 커밋: `5e55e19d`.

별도 폴더 시간 비교 도구는 계정의 토큰 갱신 POST 응답을 기다리다 중단되어 표본을 얻지 못했다. 이 시도에서는 시험 폴더가 생성되지 않았고 기존 설정 해시도 유지됐다. 앞의 실제 백업·복구 검증은 별도 실행에서 성공했다. 이 두 결과를 설치된 앱의 속도나 토큰 지연으로 동일시하지 않는다.

실제 장시간 백업의 처리량은 새 시험본을 설치한 뒤 같은 작업의 완료 기록으로 비교해야 한다. macOS 실기기·실계정 검사는 별도다.
