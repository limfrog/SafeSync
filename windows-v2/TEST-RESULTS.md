# SafeSync Windows 1.0.0-preview.9 검사 기록

## preview.9 탭 작업 공간 · 중복 사본 비교 (2026-10-19)

- 실행 중 preview.8의 접근성 목록과 진단 정보를 읽었다. 연결된 작업의 결과는 동일 17,868개 / 반복 충돌 57개 / 일반 오류 0개였다. 저장된 원격 카탈로그의 실제 중복 경로는 12개이며 상위 폴더도 관련 경로 충돌로 표시되고 있었다. 진단에 표시된 최상위 폴더 자체가 실제로 중복이라는 뜻은 아니다. 사용자 파일명과 실제 경로는 공개하지 않는다.
- 실계정 읽기 전용 검사에서 계정 설정 파일의 SHA-256이 유지됐고, 쓰기 차단 HTTP 처리기로 Google Drive 업로드·이름 변경·삭제 요청을 허용하지 않았다. 일반 파일 3개의 내용 체크섬 일치를 확인했다. 실제 충돌 경로 표본도 별도 보고서에 기록한다. 실행 중 앱·스냅샷·원격 사본을 고쳐 결과를 꾸미지 않는다.
- 회귀 검사: Google Drive의 중복 부모 폴더 ID 탐색, 동일 내용 전체 사본 통과, 하나라도 다른 체크섬이면 충돌, 확인된 선택만 강제 처리, 비교 후 사본 집합 변경 거부, 위조 상위 ID 거부, ID별 보존 이름 변경, 중단·응답 손실 후 사본 보존, 파일/폴더 혼합 충돌 거부, 하위 변경 피드 반영 및 안정된 중복 폴더의 반복 전체 탐색 방지를 검사한다.
- 단방향/양방향의 덮어쓰기·역방향 복구·둘 다 보관·이름만 정리 및 휴지통 보존을 검사한다. 동일 중복 파일을 양방향의 삭제 기준으로 잘못 쓰지 않는지 검사한다.
- UI: 한 최상위 창의 세 탭, 휴지통 탭 재방문 시 목록 보존, 작업/활동기록 실제 드래그와 저장, 축소 시 로그·상태줄, 메인 문제 해결 아이콘 제거, 중복 사본 상세·보존 선택·확인 취소, 기존 파일 방향 선택·이력 읽기 전용을 라이트/다크에서 검사한다. 작은 탭의 전체 조작부는 바깥 스크롤로 접근할 수 있다.
- 최종 묶음은 핵심·화면·설치·설치 후 화면 검사를 다시 실행한 뒤 전달한다. 검사 횟수와 설치파일 해시는 완료된 산출물을 기준으로 한다. 아래는 이전 버전 당시 기록이다.

## preview.8 하단 문제 해결 통합 (2026-10-19)

- 독립 문제 해결/비교 Window를 UserControl로 전환하고 동기화 상태의 하단 탭에 장착했다. 새 해결 창이 생기지 않는지, 메인창을 막지 않는지, 오류/충돌/작업 연결 조치가 같은 영역에서 동작하는지 검사한다.
- 라이트/다크 렌더링, 720×600 축소에서 처리 버튼 가림, 작업 이력 선택과 처리 권한 연동, 과거 결과 변경 금지, 같은 이력 갱신/창 숨김 시 선택 보존, 새 이력에서 이전 선택 폐기, 세션 이력이 없는 저장 오류 안내/재시도를 검사한다.
- 실제 적용 버튼의 확인 취소/역방향 검증 복사/휴지통 보존, 실제 재시도 버튼에서 격리된 스케줄러를 통한 완료 복귀, Dropbox 생성일시 구분 및 대괄호가 있는 실제 파일 이름 분류를 유지·검사한다. 현재 실행 앱과 실계정 클라우드·NAS는 변경하지 않는다.
- 엔진 동작은 이전 버전과 동일하며 최종 패키지는 핵심 회귀 검사 및 설치 후 화면 검사까지 다시 실행한다. 최종 결과는 이번 빌드 산출물을 기준으로 한다.

- 실계정 클라우드·NAS 파일이나 현재 실행 중인 앱은 변경하지 않는다. 최종 검사 결과는 이번 빌드의 격리 산출물을 기준으로 한다. 아래 이전 버전 기록은 당시 상태를 기술한다.

## preview.6 실패 → 해결 → 작업 재시도 검증 (2026-10-19)

- 현재 열린 앱은 여전히 preview.2이며 Recent가 같은 중복 이름으로 실패하고 있음을 창/로컬 기록에서 확인했다. 실행 중인 앱·실제 백업 파일은 수정하지 않았다.
- 실패 시 메인창/동기화 상태 결과/메시지 창에서 해결 화면으로 연결한다. 오류 분류별 안내, 클라우드 위치 열기/재연결/계정 연결, 작업 설정, 재시도, 일단 대기 선택지를 제공한다.
- 해결용 진단 정보는 메시지 목록과 분리 저장하고 정상 완료 시에만 해제한다. 반복되는 작업 수준 실패가 알림 키 불일치로 다시 표시되던 문제도 고쳤다.
- 합성 오류 분류·원문 보존·진단 영속성, 메시지 비운 뒤 해결 UI 유지, 라이트/다크 화면, 작은 창에서 버튼/상태줄 가림, 과거 실패 기록의 재시도 차단을 검사한다.
- 실제 앱 재시도 버튼 → 스케줄러 → 격리된 로컬 파일 복사 → 완료 이벤트까지 검사한다. 테스트는 현재 실행 앱의 백업 잠금/실제 계정/실제 파일과 분리한다. 클라우드 복구 동작은 기존 격리 회귀 검사이며 이번에 실계정 파일은 변경하지 않는다.
- 아래는 이전 프리뷰의 검증 기록이다. 최종 배포본 검사 수와 결과는 이번 빌드의 격리 검사 산출물을 기준으로 한다.

## preview.5 클라우드 재연결 · 중복 경로 · 메시지 검증 (2026-10-19)

- 현재 실행 중인 preview.2 창을 읽어 Recent의 실제 실패 원인이 Google Drive의 중복 이름임을 확인했다. 이전 작업 ID의 계정 불일치 메시지도 남아 있었다. 실제 계정/작업/백업 파일은 수정하지 않았다.
- 계정·루트 변경 또는 가져온 작업의 확인 요구, 명시적 폴더 선택 뒤 새 작업 ID/기준 생성, 취소 시 보존, 선택 도중 계정 변경 거절, 기존 스냅샷 보존 및 양방향 초기 합집합을 검사했다.
- 중복 파일·폴더·하위 경로를 보호하면서 다른 경로가 계속 백업되는지, 삭제가 잘못 전파되지 않는지, 재시작에도 중복 상태를 기억하고 전체 재열거 없이 재확인하는지, 중복 해소 뒤 처리가 재개되는지 검사했다.
- 메시지 비우기는 확인한 항목만 제거하고 새로 도착한 메시지는 보존한다. 미해결 중복 알림 억제, 재시작 후 억제 유지, 해결 후 재발/다른 오류의 재알림을 검사했다.
- 핵심 검사 577개 통과: `safesync-v2-31ac81bc760e4a85a679dd53c8770194`. 라이트/다크 UI 및 설치본 검사는 최종 빌드의 격리 결과를 기준으로 한다. 실제 클라우드 파일을 변경하는 실계정 검사는 이번 수정에서 실행하지 않았다.
- 첫 통합 빌드의 화면 검사 360개, 설치 검사 34개, 실제 페이로드 499개 해시 및 설치 후 화면 검사 360개가 통과했다. 메시지 창의 라이트/다크 모습을 렌더링해 확인했다. 최종 연결 보정은 새 위치에 이전 충돌 처리 결정을 재사용하지 않으며, 작업 편집에서 확인 요구를 해제할 때도 새 기준을 생성한다. 최종 배포본에서 동일 검사들을 다시 실행한다.
- 표시 이름은 SafeSync로 바꾸고 기존 앱 소유의 SafeSync 2 바로 가기만 정리한다. 설치/데이터 내부 경로와 등록 식별자는 호환성을 위해 유지한다.

## preview.4 종료 중 → 대기 상태 검증 (2026-10-19)

- 동기화 이력에 Stopping/Waiting을 추가했다. 종료 요청 즉시 ‘종료 중…’을 표시하고 마지막 파일의 진행 보고가 와도 유지하며, 종료 결과는 ‘대기 중’으로 남긴다. 종료 중에는 일시정지 버튼을 표시하지 않는다.
- Stopped와 Paused를 분리하고 preview.3의 종료 작업 호환용 Paused 표시는 읽을 때 해제한다. 실제 전송 중단 경계와 파일 검증·교체 방식은 유지한다.
- 로컬/Google/Dropbox × 단방향/양방향 6조합에서 마지막 파일 완료·다음 파일 보류·일시정지가 아닌 대기·재시작 후 자동 실행 억제·명시적 시작을 검사한다. 라이트/다크 상태창의 즉시 표시, 마지막 진행 중 표시 유지 및 대기 결과도 회귀 검사한다.
- 아래 preview.3 및 이전 기록은 당시 동작과 검사 이력이다. 이번 빌드의 최신 결과는 배포본과 함께 생성된 격리 검사 결과를 기준으로 한다.

## preview.3 비교·안전 종료 검증 (2026-10-19)

- 실행 중 앱의 기록에서 Work Backup의 생성 시각 관련 충돌 15,649개를 확인했다. 대표 5개는 크기·수정 시각이 같고 생성 시각만 달랐으며, 대표 3개의 실제 SHA-256도 일치했다. 실제 파일/설정은 읽기만 했다.
- 단방향 로컬/NAS의 생성 시각 오판 제거, 수정 시각이 다른 같은 크기 파일의 체크섬 동일 확인, 실제 다른 내용·크기 충돌 유지, 잠금 대기 및 기존 알림 해소 회귀를 추가했다. Google/Dropbox는 서비스 체크섬을 사용한다.
- 지정 NAS의 새 `SafeSync-comparison-validation-*` 폴더에서 생성 시각이 약 3년 달라도 같은 파일을 건너뛰고, 수정 시각이 달라도 내용이 같으면 교체하지 않는 것을 확인했다. 결과 `safesync-v2-16bda9b6348a4b75b432b26c5ccefbc7/nas-comparison-result.json`. 기존 백업은 변경하지 않았다.
- 작업 종료는 로컬/Google/Dropbox × 단방향/양방향 6조합에서 현재 파일의 완료, 다음 파일 미실행, 미처리 경로 보존, 자동 실행 억제, 종료 상태 저장, 재시작 후 대기, 명시적 재개를 검사했다. 시작 전 비교와 계정별 작업 잠금 대기에서도 안전하게 끝난다.
- 종료 대기는 Stopped와 Paused를 함께 저장해 이전 프리뷰로 돌아가더라도 자동 실행하지 않도록 한다. 실행 중 PauseGate는 풀어 현재 파일을 마무리하며 진행 이력에는 실제 일시정지로 잘못 표시하지 않는다.
- 첫 추가 회귀 530개, UI 330개, 설치 복구 33개 및 실제 설치 페이로드 499개 해시 검사가 통과했다. 마지막 진행 이력 보정 회귀는 최종 빌드 결과에 포함한다. 아래는 이전 공개 프리뷰의 이력이다.

## 이전 1.0.0-preview.1 검사 기록

## 현재 프리뷰 검사

- Release 빌드 경고 0·오류 0, 핵심 회귀·장애 주입 **448개 통과**.
- 번들 런타임 EXE의 라이트/다크 UI·창 종료 **316개 통과**. PowerShellLoaded=false, BundledRuntime=true, ProcessExited=true.
- 설치/업데이트/제거·강제 종료 복구 **33개 통과**. 실제 격리 설치 페이로드 **498개 SHA-256 일치**.
- Google Drive 실제 계정 양방향 **35개 통과**, Dropbox 실제 계정 양방향 **32개 통과**.
- 지정 NAS의 로컬→NAS/NAS→로컬 각각 11단계, 총 **22단계 통과**. 수정·삭제 전파, 충돌 처리, 잠금, 재시작, 빈 폴더를 확인했다.
- 손상된 클라우드 다운로드를 원본에 반영하지 않음, 이전 성공 스냅샷 보존 및 정상 다운로드 재시도를 합성 검사했다.

## preview.8 발견·수정 및 실제 환경 시험

native delta를 반영하지 않던 가져오기 경로를 수정하고, 오래된 확장 필드의 Generation이 새 세대를 덮어쓰지 않도록 했다. 안전한 조회와 요청 제한 응답에는 최대 4회 지수 재시도/jitter/Retry-After를 적용한다. 긴 Retry-After는 앱 실행 중 계정별로 공유해 새 작업이 대기를 우회하지 않는다. 실제 서버의 성공 여부가 불분명한 생성/이동/전송 오류는 무조건 재실행하지 않고 저널/세션 조회로 판정한다.

설치 부트스트랩에서 긴 경로의 .NET Framework I/O 실패를 재현하고 확장 경로 처리로 수정했다. 설치 도중 old-moved/published 경계에서 검사 자식 프로세스를 실제 종료해 이전 버전 복원을 확인했다. 손상/누락 페이로드·경로 이탈·기존 다른 파일 거절, 사용자 추가 파일 보존, 제거/중단된 제거 후 재설치를 검사했다. 설치 목록/소유 표시는 제거 중 장애 후 복구를 위해 남긴다. 실제 전체 페이로드를 격리 설치하여 파일 해시, 번들 런타임으로 UI 실행/프로세스 종료, 앱 파일 제거까지 확인했다. 실제 기본 설치 위치/레지스트리/바로 가기는 변경하지 않았다.

환경설정 최소 폭을 명시하고 최소 크기에서 하단 버튼 노출을 검사했다. 도움말/하단 버전은 어셈블리 정보에서 읽도록 바꿔 구버전 번호가 남지 않게 했다. 설치 종료 요청의 CRLF 명령도 회귀 검사한다.

NAS 시험 위치와 방향별 측정, 남은 출시 조건은 [배포 검증 현황](RELEASE-VALIDATION.md)에 기록했다. 별도 부하 검사에서는 복사 도중 자식 프로세스를 실제 종료해 기존 사본 보존과 재복사를 확인했다. 작업 집합은 시작 48.3 MiB·최고 66.6 MiB·종료 59.4 MiB였으며 짧은 관측일 뿐 메모리 누수 부재를 증명하지 않는다.

## preview.4 진행률 오류 회귀 (계속 유지)

사용자 화면에서 확인한 읽기 전용 `Percent` 양방향 바인딩 예외를 기존 XAML과 새 검사로 동일하게 재현했다. 수정 전 검사에서 `XamlParseException`이 발생했고, `ProgressBar.Value`를 명시적으로 `Mode=OneWay`로 바꾼 뒤 같은 검사가 통과했다.

이전 82개 검사는 빈 진행 창과 창 열기/숨김은 확인했으나 활성 진행 항목의 템플릿을 생성하지 않아 이 오류를 놓쳤다. 과거 통과 결과가 실제 백업 중 UI까지 검증했다는 뜻은 아니었다.

## 검사 방법과 한계

기본 회귀 검사는 실제 사용자 설정·OAuth 토큰·기존 백업 자료를 사용하지 않는다. 별도 opt-in Google 실계정 검사는 기존 연결을 메모리에서 읽고 새 시험 폴더만 사용했다. 새 브라우저 로그인·동의, Dropbox 실계정, 조직/공유 드라이브, 실제 서비스 제한/권한 취소, 물리적 단절은 검증하지 않았다. 직접 요청 제한 재시도는 preview.8에서 모사 검사했고 Google 변경 피드/커서는 preview.9까지 실계정으로 추가 확인했다. NAS 시험도 사용자가 지정한 test 위치의 새 하위 폴더만 사용했다.

WPF 검사는 별도 데이터 루트에서 화면 렌더링·계정/작업 설정 버튼 연결·비모달 진행/휴지통·종료를 검사한다. 폴더 선택은 합성 클라우드 저장소로 새 폴더 생성·선택까지 검사하며 실제 브라우저 로그인이나 계정 권한 검사를 대신하지 않는다. CloudAccounts와 CloudFolderPicker 화면의 라이트/다크 렌더링을 포함하지만 실제 계정 정보는 표시하지 않는다.

이 결과는 정식 사용 승인이나 전체 환경의 성능 보장이 아니다. 변경 기록을 사용할 수 없는 위치의 초기 메타데이터 확인과 기본 스냅샷 로딩/시작·종료 정리는 대규모 환경에서 느릴 수 있다. USN·변경 피드·변경 조각 저장은 preview.7에 구현했으나 실제 클라우드/대량 환경 처리량 측정은 남아 있다. 클라우드 교체는 저널 기반 복구 가능 절차이며 서버 전체에 대한 원자적 교환은 아니다.
