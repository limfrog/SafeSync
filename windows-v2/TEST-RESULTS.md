독립적으로 사용하도록 수정했다. 새 원본 파일/원격 변경 피드 동시 반영,

## preview.8 발견·수정 및 실제 환경 시험

native delta를 반영하지 않던 가져오기 경로를 수정하고, 오래된 확장 필드의 Generation이 새 세대를 덮어쓰지 않도록 했다. 안전한 조회와 요청 제한 응답에는 최대 4회 지수 재시도/jitter/Retry-After를 적용한다. 긴 Retry-After는 앱 실행 중 계정별로 공유해 새 작업이 대기를 우회하지 않는다. 실제 서버의 성공 여부가 불분명한 생성/이동/전송 오류는 무조건 재실행하지 않고 저널/세션 조회로 판정한다.

설치 부트스트랩에서 긴 경로의 .NET Framework I/O 실패를 재현하고 확장 경로 처리로 수정했다. 설치 도중 old-moved/published 경계에서 검사 자식 프로세스를 실제 종료해 이전 버전 복원을 확인했다. 손상/누락 페이로드·경로 이탈·기존 다른 파일 거절, 사용자 추가 파일 보존, 제거/중단된 제거 후 재설치를 검사했다. 설치 목록/소유 표시는 제거 중 장애 후 복구를 위해 남긴다. 실제 전체 페이로드를 격리 설치하여 파일 해시, 번들 런타임으로 UI 실행/프로세스 종료, 앱 파일 제거까지 확인했다. 실제 기본 설치 위치/레지스트리/바로 가기는 변경하지 않았다.

환경설정 최소 폭을 명시하고 최소 크기에서 하단 버튼 노출을 검사했다. 도움말/하단 버전은 어셈블리 정보에서 읽도록 바꿔 구버전 번호가 남지 않게 했다. 설치 종료 요청의 CRLF 명령도 회귀 검사한다.

NAS 시험 위치와 방향별 측정, 남은 출시 조건은 [배포 검증 현황](RELEASE-VALIDATION.md)에 기록했다. 별도 부하 검사에서는 복사 도중 자식 프로세스를 실제 종료해 기존 사본 보존과 재복사를 확인했다. 작업 집합은 시작 48.3 MiB·최고 66.6 MiB·종료 59.4 MiB였으며 짧은 관측일 뿐 메모리 누수 부재를 증명하지 않는다.

## preview.7 누락 보완 회귀

기존 207개에 51개 핵심 검사를 추가했다. 초/밀리초 휴지통 조회 및 만료 삭제, 1년 지난 스냅샷에서 자동 전체 비교 없음/수동 전체 비교 유지, 변경 조각 재생·이전 세대 제외, 2,000개 파일 대비 단일 체크포인트 크기 감소, 알림의 재실행 간 중복 억제/성공 해제/재발/취소 보존, 잠금 통계, 영구 활동 로그, 목록 캐시, USN 루트 ID/저널 ID/범위·미지원 대체 및 원본/백업의 같은 파일 ID 별칭 보존, MD5/SHA-256 병행 검증, 커서와 대기 경로의 동시 저장, 커서 만료 대체 조회, Drive 103개 파일을 100+3으로 일괄 요청, Dropbox 변경 페이지, 작은 파일 최대 2개 전송·취소 후 복구, 원격 폴더 인덱스 보존, 처음 없던 원본 폴더 재연결 후 감시와 종료, 일시적 읽기 잠금 후 원자적 메타데이터 저장, 재시작한 예약 작업의 이전 잠금 파일 자동 재시도와 종료를 확인한다.

합성 2,000개 항목에서 단일 항목 체크포인트는 기본 스냅샷 크기의 1/50 미만이라는 회귀 검사를 통과했다. 이는 메타데이터 기록량 비교이며 실제 클라우드 백업 속도 배율이 아니다.

최종 검사 중 메타데이터 File.Replace에서 ‘바꿀 파일을 제거할 수 없습니다’ I/O 오류가 한 번 발생했다(합성 fixture 4018acd877664e03ac8c82af2a71a2df). 읽기 핸들은 delete sharing을 허용하고, 상태 조각의 읽기/교체를 경로별로 직렬화하며, 알려진 일시적 잠금/교체 오류에만 최대 4회 짧게 재시도하도록 보완했다. 대상 파일 삭제/직접 덮어쓰기 우회는 하지 않는다. 합성 잠금 회귀 검사와 새 폴더의 전체 검사 255개가 통과했다.

UI 검사에는 자동 시작 경로 인용/위험 경로 거절 2개를 추가했다. 합성 UI 실행은 자동 시작 레지스트리 등록과 모든 알림음을 차단한다. 실제 레지스트리 등록, 실제 NTFS USN 접근 허용, 클라우드 계정과 NAS의 장시간 성능/단절은 별도 확인이 필요하다. 도입한 안전한 차이는 [보완 기록](PARITY-AND-PERFORMANCE.md)에 구분했다.

## preview.6 휴지통 데스크톱 UI

라이트/다크 × 로컬/Google Drive/Dropbox의 6개 조합에 108개 UI 검사를 추가했다. 합성 63개 항목으로 이름/경로 검색·검색 시 선택 해제·검색 결과 전체 선택·선택 수와 용량·전체 경로·작업 중 복구/삭제 차단·닫기 활성 상태·비모달 창·공급자별 삭제 정책·테마 스크롤바·좁은 창 하단과 표 최소 폭·검색 결과 없음 표시를 확인했다. 일반/좁은 창 화면을 렌더링하여 라이트/다크 배치를 육안 확인했다.

휴지통의 실제 목록/복구/삭제 엔진은 유지하며 검색은 메모리의 조회 결과에만 적용한다. UI 검사는 합성 자료를 사용하며 실제 사용자 휴지통이나 클라우드 파일을 복구/삭제하지 않는다.

## preview.5 세션 이력 및 데스크톱 UI

추가한 핵심 검사는 반복 실행의 개별 기록·원본/대상/작업 이름의 불변 복사·결과 목록 스냅샷·완료/변경 없음/실패/중단·일시정지·경과 시간·새 세션 초기화를 확인한다. 실제 스케줄러의 Started/Progress/Completed를 합성 로컬 폴더에 연결하여 상태 창이 없는 자동 실행도 기록되는지 확인했다.

WPF 검사에서는 라이트/다크 각각에서 동일 작업의 반복 결과 보존, 과거 행 선택 후 새 진행이 와도 선택 유지, 최신 실행으로 복귀, 진행 창의 일시정지/재개, 숨긴 상태에서 발생한 실패의 상세 표시, 과거 충돌 덮어쓰기 차단, 독립 창 유지, 분할 높이 저장, 좁은 창의 상세 영역·하단 안내·열 최소 폭을 확인했다. 일반/충돌/좁은 화면 이미지를 생성하고 라이트/다크 화면을 육안 확인했다.

UI 이력은 실제 클라우드가 아닌 합성 이벤트/파일로 검사한다. 과거 오류/충돌 행은 이후에 해결되더라도 당시 결과로 남으므로 상단 주의 이력 숫자는 현재 미해결 파일 수가 아니다. 이력은 메모리 전용이며 재실행하면 초기화한다.

## preview.4 진행률 오류 회귀 (계속 유지)

사용자 화면에서 확인한 읽기 전용 `Percent` 양방향 바인딩 예외를 기존 XAML과 새 검사로 동일하게 재현했다. 수정 전 검사에서 `XamlParseException`이 발생했고, `ProgressBar.Value`를 명시적으로 `Mode=OneWay`로 바꾼 뒤 같은 검사가 통과했다.

추가한 72개 UI 검사는 라이트/다크 × 로컬/Google Drive/Dropbox 조합에서 실제 `OnProgress` → `RefreshProgress` → WPF 항목 템플릿 생성 경로를 실행한다. 총량 미정(0/0)·0/12·1/12·6/12·12/12의 값과 단방향 연결, 숨긴 상태의 갱신 후 다시 표시, 완료 시 항목 제거와 UI 활성 상태를 확인한다. 실제 계정으로 업로드하지 않고 합성 진행 이벤트만 사용한다.

이전 82개 검사는 빈 진행 창과 창 열기/숨김은 확인했으나 활성 진행 항목의 템플릿을 생성하지 않아 이 오류를 놓쳤다. 과거 통과 결과가 실제 백업 중 UI까지 검증했다는 뜻은 아니었다.

preview.4 검사 환경 이력: 제한 환경의 DPAPI 합성 검사가 실패해 승인된 환경에서 재실행했다. 별도 전체 검사에서 임시 상태 파일의 `File.Replace` I/O 실패가 한 번 발생했고, 새 격리 폴더의 재실행에서 185개가 통과했다. 이 파일 교체 실패의 원인은 확정하지 않았으며 UI 수정과는 별개로 기록한다. 실제 사용자 설정이나 백업 파일은 이 검사에 사용하지 않았다.

## 핵심 검사 범위

핵심 검사에는 기존 62개의 로컬 파일 보존·해시·원자적 교체·충돌·잠금·휴지통·스케줄러 검사와 다음 항목을 포함한다.

- 두 공급자의 최초/동일/증분 백업, 충돌이 다른 파일 처리를 막지 않음, 충돌 우측 메타데이터, 기존 이름 변경 후 복사
- 삭제의 휴지통 이동, 평면 목록, 선택 복구/삭제, 위조 경로 차단, 잠금 파일의 일반 오류 제외 및 해제 후 재시도
- 업로드 체크섬 불일치 시 원본 백업 보존·새 세션 재시도
- 이전 백업 이동 직후 중단·새 파일 이동 응답 유실·교체 후 해시 실패의 복구/롤백
- 외부 클라우드 변경 감지 시 덮어쓰기 차단, 사용자가 포기한 이전 의도의 재실행 차단
- 계정 바인딩 불일치 차단, 미완료 전송이 사용하는 휴지통 사본 보호
- Google 분할 전송의 308 Range 확인 후 정확한 위치에서 재개, 빈 파일, 진행 없는 세션 반복 제한, 같은 폴더 이름 변경 시 부모/수정 시간 유지
- Google Drive·Dropbox 새 폴더 API의 이름·부모 경로 확인, 중복 이름/위험 경로/내부 보관 이름 차단, 현재 위치의 하위 폴더 생성
- 실제 폴더 선택 창의 라이트·다크 목록/선택 글자/스크롤바/입력칸, 폴더 생성 후 이동·선택 ID 반환, 생성 중 중복 요청 차단·취소, 중복/권한 오류 후 UI 복구
- Dropbox 페이지 커서, `incorrect_offset` 복구, 만료 세션 재시작, 한글 이름의 ASCII HTTP 헤더 직렬화, 개인 계정용 `delete_v2`
- HTTPS 목적지 제한·위장 도메인 차단·401 단일 강제 갱신·액세스 토큰 캐시
- PKCE/S256·상태값 검증·잘못된 콜백 거절 후 정상 콜백 수신
- 합성 DPAPI 및 레거시 무접두 DPAPI/AES 인증 정보 호환·AES 변조 차단
- 기존 스냅샷의 세대 일치 델타 반영·불일치 조각 제외·대기 경로 승계·계정 재보호·키 미복사
- 위험한 스냅샷/미완료 원본 트랜잭션 거부, 실패한 가져오기가 활성 설정/스냅샷을 바꾸지 않음

## 검사 방법과 한계

기본 회귀 검사는 실제 사용자 설정·OAuth 토큰·기존 백업 자료를 사용하지 않는다. 별도 opt-in Google 실계정 검사는 기존 연결을 메모리에서 읽고 새 시험 폴더만 사용했다. 새 브라우저 로그인·동의, Dropbox 실계정, 조직/공유 드라이브, 실제 서비스 제한/권한 취소, 물리적 단절은 검증하지 않았다. 직접 요청 제한 재시도는 preview.8에서 모사 검사했고 Google 변경 피드/커서는 preview.9까지 실계정으로 추가 확인했다. NAS 시험도 사용자가 지정한 test 위치의 새 하위 폴더만 사용했다.

WPF 검사는 별도 데이터 루트에서 화면 렌더링·계정/작업 설정 버튼 연결·비모달 진행/휴지통·종료를 검사한다. 폴더 선택은 합성 클라우드 저장소로 새 폴더 생성·선택까지 검사하며 실제 브라우저 로그인이나 계정 권한 검사를 대신하지 않는다. CloudAccounts와 CloudFolderPicker 화면의 라이트/다크 렌더링을 포함하지만 실제 계정 정보는 표시하지 않는다.

이 결과는 정식 사용 승인이나 전체 환경의 성능 보장이 아니다. 변경 기록을 사용할 수 없는 위치의 초기 메타데이터 확인과 기본 스냅샷 로딩/시작·종료 정리는 대규모 환경에서 느릴 수 있다. USN·변경 피드·변경 조각 저장은 preview.7에 구현했으나 실제 클라우드/대량 환경 처리량 측정은 남아 있다. 클라우드 교체는 저널 기반 복구 가능 절차이며 서버 전체에 대한 원자적 교환은 아니다.
