# Windows preview.28 · macOS 0.3.24(33)

2026-10-28. Google Drive 보관 종료 후 자체 휴지통 이동.

## 동작

백업 중 교체·삭제되는 파일은 기존처럼 먼저 SafeSync 휴지통에 보관한다. 기본 보관 기간 100일이 지나 자동 정리하거나 사용자가 SafeSync 휴지통에서 사본을 제거하면, Google Drive는 `files.update`의 `trashed=true`로 **Google 자체 휴지통**에 보낸다. 일반 Google 정책에서는 그 뒤 30일 동안 복원할 수 있으며 그동안 저장 공간을 사용한다. [Google 공식 정책](https://developers.google.com/workspace/drive/api/guides/delete).

응답의 파일 ID와 휴지통 상태가 일치해야 성공으로 처리한다. 권한 오류·잘못된 응답·미확인 상태가 발생해도 영구삭제로 대체하지 않는다. Windows는 기존 `.safesync-trash/` 범위 제한을 유지한다. macOS는 보관 사본 제거 경로를 별도 인터페이스로 구분하고, Google 휴지통 이동을 구현하지 않은 연결은 안전하게 거절한다. 폴더 사본을 보낼 때 폴더 ID 기반 캐시도 무효화한다.

Windows와 macOS의 버튼·확인창은 Google 휴지통 이동 및 복구 기간·저장 공간 사용을 안내한다. Dropbox 일반 삭제와 자체 복구 정책, 로컬 파일의 명시적인 완전삭제는 그대로다. 연결 검사용 시험 폴더·미완료 전송의 임시 객체와 복구를 마친 빈 내부 컨테이너는 별도 정리한다.

## 삭제 전파 체크박스

사용자가 기존 체크박스 위치를 확인하는 것으로 요청을 조정했으므로 **세 번째 동기화 방식은 추가하지 않았다.** 기존 `SyncMode`, `MirrorDeletes`, 작업 설정·스냅샷·권한 범위는 변경하지 않았다.

Windows: **메인창 → 작업 선택 → 작업 관리 → 작업 수정** 아래쪽, **대량 변경 보호 바로 위**의 **원본에서 사라진 파일은 백업 위치의 SafeSync 휴지통으로 이동**. 작은 창에서는 스크롤한다. 켜면 단방향에서 원본 삭제를 백업에만 반영하고, 끄면 원본 삭제 후에도 백업 사본을 남긴다. 양방향은 양쪽 삭제를 반영하므로 이 선택이 비활성화된다. macOS도 작업 설정의 동일한 삭제 반영 옵션을 유지한다.

## 검사

- Windows: 신규 Google 처리 검사 **18개** 통과. 정상 이동, 반복 호출, 권한 거부, 거짓 휴지통 상태·잘못된 ID 응답, 영구삭제로의 대체 차단, 임시 자료 정리, 현재 백업 직접 삭제 거절을 검사했다. 기존 검사와 합쳐 **1,577개**, UI **659개**가 로컬 격리 검사에서 통과했다. 라이트/다크·작은 창에서 공급자별 삭제 버튼·Google 복구/용량 안내도 검사한다.
- macOS: Google 전송 계층의 실제 코드에 시험 응답을 연결해 PATCH 본문·파일 ID·휴지통 상태·권한 거부와 영구삭제 대체 차단을 검사한다. 코어의 수동 보관 제거와 기간 만료가 이 경로를 호출하며 현재 백업이 그대로인 것을 확인한다. **XCTest 29개**, 실제 앱 Store 회귀 **24개**, 코어 시나리오·Universal arm64/x86_64·번들·임시 서명 검사가 통과했다. [macOS 실행 40613551277](https://github.com/limfrog/SafeSync/actions/runs/40613551277), 소스 `ce4d1dc`.
- Windows 최종 설치본은 [실행 40613759542](https://github.com/limfrog/SafeSync/actions/runs/40613759542), 소스 `2219e59`에서 Server 2022/2025의 격리 NTFS·loopback SMB·재시작·USN·삭제 보호·실제 VSS 읽기/정리와 설치·실행·제거 검사가 통과했다.

사용자의 실제 실행 중 앱·클라우드 계정·백업 파일·토큰·설정을 변경하지 않았다. 이번 Google 요청 검사는 격리된 HTTP 응답과 메모리 저장소를 사용했으며 실계정 서비스 호출을 수행하지 않았다. 모든 서비스 장애·NAS 조합·공급자 정책을 보증하는 검사는 아니다. 대량 변경 보호·사본 체크섬·루트 확인·미완료 전송 보호·VSS 선택 정책과 Google `drive.file` 단방향 범위는 유지한다.
