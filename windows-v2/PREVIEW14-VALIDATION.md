# Windows 1.0.0-preview.14 문제 해결 접근 수정

2026-10-21 · Horizon Entertainment · apps@horizonent.co.kr

## 확인한 원인

실행 중인 Windows preview.12의 접근성 화면에서 Work Backup 문제 목록이 ‘이전 실행 기록 / 읽기 전용’이며 처리 버튼 전체가 비활성화됨을 확인했다. 기존 구현은 최신 종료 이력에서만 비교 정보를 읽고 처리할 수 있었다. 이전 이력의 ‘정보 다시 확인’도 실제 현재 파일을 읽지 않았고, 오류 목록의 비교 버튼은 활성화돼 있어도 최신 이력이 아니면 동작하지 않았다. 이 문제는 격리된 WPF 화면 검사에서도 수정 전에 재현했다.

## 수정

- 이전 오류/충돌 목록에서도 비교 공간을 열 수 있다. 열기만으로 파일 처리 권한을 부여하지 않는다.
- ‘현재 파일 다시 비교’는 현재 선택 파일의 양쪽 메타데이터를 새로 읽고 이전 선택을 지운다. 이후에만 가능한 처리 방법을 선택할 수 있다.
- 현재 실행 세대를 재확인 정보에 연결한다. 새 실행이 시작되면 이전 선택과 적용 권한은 다시 잠기고, 그 실행이 끝나도 자동으로 되살리지 않는다.
- 작업 ID·원본·백업·서비스·동기화 방향·클라우드 계정 및 폴더 ID를 이력과 대조한다. 설정이 달라진 기록은 처리하지 않는다.
- 같은 작업이 실행 중이면 비교 공간에서 ‘현재 파일 마치고 종료’를 제공한다. 파일 경계의 기존 안전한 종료 경로를 사용하며 강제 종료나 일시정지가 아니다. 대기 후 사용자가 현재 파일을 재비교한다.
- 실제 적용은 기존 확인 창, 선택 전체의 선행 검증, 파일별 재검증, 검증 복사 및 이전 사본 휴지통 보존 경로를 그대로 사용한다.
- 버전 하단의 ‘C#/.NET 전환 검증본’, 대기 상태의 ‘전환 검증본’, 시작 기록의 ‘이전 PowerShell 버전과 설정 공간을 분리했습니다’ 표현을 제거한다. 데이터 폴더와 보호 처리는 유지한다.

## 확인 결과

- 전체 격리 백업·복구·보안 회귀 검사 **1,004개 통과**. 이력의 계정/폴더/위치/방향 고정과 세대 조회 회귀 7개를 추가했다.
- 라이트·다크 화면 검사 **585개 통과**. 이전 결과의 최초 쓰기 차단, 현재 파일 재조회 후 네 가지 처리 선택, 새 실행 시 재차단, 종료 대기, 재확인 시 이전 선택 제거를 확인했다.
- 격리된 실제 로컬 파일로 이전 이력의 재확인 후 명시적 덮어쓰기와 이전 사본의 휴지통 보존까지 검사했다. 취소 시 무변경, 역방향 복원, 중복 사본 보존, 작은 창의 버튼 표시 검사는 계속 통과했다.
- 버전 하단과 새 시작 활동기록의 문구 제거를 화면 코드로 검사했다. 이미 저장된 과거 활동기록은 삭제하지 않는다.
- 앱 빌드는 경고 0개·오류 0개.

## 범위

실제 사용자의 실행 중 앱을 종료하거나 업데이트하지 않았고 실제 작업·계정·NAS·클라우드 파일은 바꾸지 않았다. 실제 화면은 상태 확인만 했으며 파일 처리는 전용 임시 폴더에서 검사했다. 설치본·체크섬의 최종 검증은 별도 패키지 결과에 기록한다. 이 기록은 설치본 준비 단계이며 이후 배포는 저장소의 인계 기록을 확인한다.
