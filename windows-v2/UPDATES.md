# 앱 업데이트

Windows 1.0.0-preview.13 / macOS 0.3.9부터 지원합니다. 이전 버전은 이 기능이 없으므로 이번 설치 파일을 한 번 직접 설치해야 합니다. 작업·계정·스냅샷을 초기화하지 않습니다.

## 사용 방법

- 환경설정의 **업데이트 확인**으로 즉시 확인합니다. Windows 도움말과 알림 영역 메뉴, macOS 메뉴 막대에도 확인 항목이 있습니다.
- 기본값은 앱 실행 약 20초 후, 이후 매시간 자동 확인하며 새 버전을 찾으면 자동 다운로드합니다. 환경설정에서 자동 확인과 자동 다운로드를 각각 끌 수 있습니다. 설정을 바꾼 뒤 **설정 저장**을 누르세요. 자동 확인을 꺼도 수동 확인·다운로드는 가능합니다.
- 새 버전이 있으면 앱에 표시합니다. Windows에서 창이 숨겨져 있으면 업데이트 창을 강제로 띄우거나 소리를 내지 않고 알림 영역 아이콘·설명에 표시합니다. 같은 버전을 반복 팝업하지 않습니다.
- **다운로드는 설치와 다릅니다. 설치를 사용자 승인 없이 실행하지 않습니다.**
- Windows: 다운로드와 검증이 끝난 뒤 **업데이트 설치**를 누르고 확인합니다. 새 백업 시작을 막고 실행 중인 각 작업의 현재 파일을 안전하게 마친 뒤 앱을 종료하고 설치 프로그램을 실행합니다. 대기 중인 변경 경로와 기존 작업 설정은 유지합니다. 설치 대기는 취소할 수 있습니다.
- macOS: **다운로드한 ZIP 열기**로 Finder에서 확인합니다. 진행 중인 백업을 마친 뒤 기존 앱을 종료하고 ZIP을 풀어 기존 SafeSync.app을 교체하세요. 실행 중인 앱을 자동으로 덮어쓰지 않습니다.
- 네트워크 오류·취소·손상 시 백업 실패로 바꾸지 않으며 업데이트 창에서 다시 시도할 수 있습니다.

## 무결성과 한계

HTTPS로 공식 `limfrog/SafeSync` 저장소의 고정 업데이트 목록만 조회합니다. 목록과 설치 파일 모두 다른 서버로의 리다이렉트를 따르지 않습니다. 허용하는 파일명·경로·용량을 제한하고 크기와 SHA-256을 확인한 후에만 설치 파일로 확정합니다. Windows는 설치 직전 다시 확인합니다. 전송 중인 파일은 `.part`로 분리하며 정상 취소·실패 시 제거합니다. 프리뷰 숫자를 올바르게 비교하고 정식 버전을 프리뷰로 자동 전환하지 않습니다.

체크섬은 전송 오류와 파일 변경 검출용이며 독립적인 코드 서명을 대체하지 않습니다. GitHub 저장소 자체의 탈취까지 방어하는 서명된 업데이트 체계는 아닙니다. Windows 배포본은 아직 코드 서명 전이며 macOS는 ad-hoc 서명·Apple 공증 전입니다.

업데이트 확인은 파일 내용·경로·계정·토큰·실행 기록을 보내지 않습니다. GitHub 접속 과정에서 IP 주소 등 일반적인 연결 정보가 GitHub에 전달될 수 있습니다. 확인과 다운로드를 끄면 자동 업데이트 네트워크 접속을 하지 않습니다.

## 배포 담당자

1. 새 앱의 버전을 올리고 검사·빌드를 완료합니다.
2. `dist/`에 Windows 설치 EXE / macOS Universal ZIP을 넣고 실제 SHA-256을 `dist/SHA256SUMS.txt`에 기록합니다. 파일은 Git LFS 포인터가 아닌 원본이어야 합니다.
3. `node scripts/publish-updates.mjs`로 `updates/latest.json`을 생성하고 설치 파일·체크섬·목록을 함께 게시합니다. 이 스크립트는 체크섬 목록에서 최신 배포를 선택합니다. 파일을 업로드하지 않은 소스 커밋만으로 알리지 않습니다.
4. GitHub의 **Publish update catalog** 작업도 체크섬 목록이 변경되면 목록을 갱신합니다. 게시 후 원격 파일의 크기·SHA-256과 실제 업데이트 확인을 검증하세요.
5. Windows 정식 사용자는 새 프리뷰 알림을 받지 않습니다. 정식 배포를 시작한 뒤 프리뷰 채널을 따로 운영하려면 배포 채널을 추가해야 합니다.
