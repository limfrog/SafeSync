# SafeSync Windows 네이티브 전환 현황

2026-10-19: 공개 버전은 **1.0.0-preview.1**로 재정리했다. 내부 `windows-v2`, `SafeSync2-Preview` 데이터 폴더, 설치 경로·제어 채널은 이미 만든 프리뷰 데이터와 호환되도록 유지한다. 구버전 Windows 다운로드는 공개 저장소에서 제거하되 소스 변경 이력과 macOS 파일은 보존한다. Google 양방향 35개, Dropbox 실계정 32개, NAS 양방향 22단계 검사가 통과했다. 현재 결과는 TEST-RESULTS.md를 우선한다. 아래 단계 번호는 이전 개발 이력이다.

## 원칙

1. `outputs/SafeSync/`의 1.9.15 소스와 `dist/` 기존 배포본은 보존한다.
2. PowerShell을 숨겨 실행하는 방식이 아니라 WPF UI와 백업 엔진을 C#으로 이식한다.
3. 미구현 기능을 성공으로 표시하거나 기존 코드에 몰래 위임하지 않는다.
4. 검증본은 분리된 데이터 폴더를 사용하고 가져온 작업을 정지 상태로 둔다.
5. 기존 데이터 승계는 복사본에서 왕복·복구 검사를 통과한 뒤 활성화한다.

## 코드 지도

- `src/SafeSync.Core/Models.cs`: 작업·설정·스냅샷·진행/충돌 자료형, 비동기 일시정지
- `Persistence.cs`: 원자적 JSON 저장, 설정·상태 세대 읽기, 경로 검증
- `LegacyMigration.cs`: 기존 DPAPI/AES 계정과 스냅샷·델타 체크포인트의 복사 승계, 실패 시 기존 세대 유지
- `VerifiedFiles.cs`: SHA-256 임시 사본, Windows 원자적 교체, 트랜잭션 복구, 휴지통
- `BackupEngine.cs`: 비교·증분 작업·충돌·잠금·파일별 체크포인트
- `BackupScheduler.cs`: 변경 감지, 예약, 재시도, 종료 취소·작업 대기
- `SyncSessionHistory.cs`: 실행별 세션 이력·결과 스냅샷·일시정지·시각/경과·최신 실행 구분. 메모리 전용
- `src/SafeSync.App/SessionHistory.cs`: 이력 선택·최신 추적·읽기 전용 과거 결과·분할 영역 크기 제한
- `src/SafeSync.App/TrashBrowserPresentation.cs` / `Views/Trash.xaml`: 로컬·클라우드 공통 휴지통 검색/선택 요약·테마·비모달 데스크톱 UI. 파일 복구/삭제 엔진은 기존 로직 유지
- `Cloud/CloudAuthentication.cs`, `Credentials.cs`, `CloudHttp.cs`: 브라우저 PKCE·토큰 갱신/보호·허용 HTTPS 주소·오류 응답 비밀정보 제외
- `Cloud/GoogleDriveStore.cs`, `DropboxStore.cs`: 서비스별 목록/메타데이터·분할 전송·세션 재개·이동/삭제
- `Cloud/CloudPublisher.cs`: 검증 사본·영속 저널·이전 파일 보관·체크섬 재검증·복구·보관 사본 보호
- `Cloud/CloudBackupEngine.cs`, `CloudTrash.cs`: 비교·증분 실행·계정 범위 직렬화·휴지통 목록/복구·보관 기간 정리
- `src/SafeSync.App/`: C# WPF 앱, 알림 영역, 기존 WPF 화면, 다이얼로그, 테마
- `CloudFolderPicker.cs` / `Views/CloudFolderPicker.xaml`: preview.3 라이트·다크 폴더 선택/생성 UI. `Cloud/CloudFolders.cs`가 단일 하위 폴더 이름과 중복 검사 수행
- `tests/SafeSync.Tests/`: 임시 테스트 폴더에서만 실행하는 파일 안전·전환 검사
- `scripts/Build.ps1`: 로컬 개발 캐시와 런타임 포함 ZIP 생성

## 검증에서 구분할 것

핵심 자동 검사는 임시 로컬 폴더·합성 설정·모사 HTTP를 사용한다. preview.8에서는 사용자가 지정한 NAS의 새 검사 폴더만 사용해 실제 양방향 전송·교체·잠금·휴지통 복구를 추가 확인했다. preview.9에서는 사용자 허용 후 기존 Google 연결을 메모리에서 읽어 새 검증 폴더의 실제 전송/복구를 확인했다. 기존 백업과 계정 설정은 변경하지 않는다. UI 테마 렌더링 통과가 모든 버튼의 실제 사용자 시나리오를 뜻하지 않는다. 보호된 계정·상태 승계는 합성 자료로 검사했으며 원본 파일을 수정하지 않는다. 새 브라우저 로그인·조직 정책·권한 변경·물리적 네트워크 단절은 별도 확인해야 한다.

preview.1: C# 핵심 검사 62개·EXE UI 검사 38개, preview.2: 161개·46개, preview.3: 185개·82개, preview.4: 185개·154개 통과. preview.4는 활성 진행 항목을 실제로 생성하는 회귀 검사를 추가해 읽기 전용 진행률의 양방향 연결 오류를 재현·수정했다. 최신 상세는 [검사 기록](TEST-RESULTS.md)에 별도 기록한다. 번들 실행은 `System.Private.CoreLib`와 WPF를 앱 폴더의 .NET 런타임에서 로드해야 하며 PowerShell 자동화 어셈블리를 로드하면 실패한다. 1.9.15 소스와 설치 EXE는 보존한다. 실제 Dropbox 전송과 대규모 성능 비교는 아직 수행하지 않았다.

## preview.8 안전성·설치 검증

native delta 승계/Generation 중복 방지, 계정별 공유 Retry-After, 조회의 안전한 재시도, 현재 사용자 전용 종료 통신, 격리 설치/업데이트/강제 종료 복구/제거·재설치 검사를 추가했다. 기본 NAS 시험과 짧은 반복 부하 시험은 통과했으며 실제 클라우드·물리적 단절·깨끗한 Windows·다일 실행은 남아 있다. [상세 현황](RELEASE-VALIDATION.md)을 참고한다.

## preview.9 Google 실계정·재시작 보완

기존 연결을 사용한 Google 실계정 시험에서 내용·시간·증분·충돌·잠금·휴지통·분할 전송 재개를 확인했다. 추가 재시작 시험에서는 원본 전체 재확인이 유효한 원격 커서까지 전체 재조회시키는 문제를 재현·수정했다. 원본 재확인은 유지하고 원격 변경 피드를 재사용한다. 수동 전체 비교와 만료 커서 복구는 회귀 검사로 보존했다. [실계정 증거](GOOGLE-LIVE-RESULTS.md)를 참고한다.

## preview.7 보완

구버전 날짜 형식 휴지통·재연결 감시·자동 시작·알림 상태·로그·잠금 통계·USN·클라우드 커서·100개 묶음 조회·작은 파일 최대 2개 전송·변경분 체크포인트·휴지통 캐시·SHA-256 우선 검증을 반영했다. 경과 일수에 의한 전체 재검사는 제거했다. 상세 및 안전하게 유지한 차이는 [보완 기록](PARITY-AND-PERFORMANCE.md)을 참고한다.
