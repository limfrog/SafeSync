# 프리뷰 23 — Google Drive 최초 백업 지연 개선

Windows 1.0.0-preview.23 / macOS 0.3.19(28), drive.file 별도 시험본.

- Windows: 새 백업의 모든 미등록 파일을 전송 전에 순차 조회하던 경로를 제거했다. 기존 원격 ID만 일괄 확인하고 새 경로는 처리 직전에 조회한다. 게시 직전 외부 파일 발생·수정·중복 검사도 유지한다.
- 새 파일은 존재하지 않는 이전 버전 보관 경로를 탐색하지 않는다. 기존 파일 교체·삭제·복구에는 기존 검증을 유지한다.
- 5MiB 이하 Google Drive 파일은 사전 발급 ID를 저널에 저장한 뒤 multipart 요청으로 보낸다. ID는 32개씩 발급해 요청을 줄인다. 전송 응답 유실 시 저장한 ID로 내용·위치를 확인하고 중복 업로드하지 않는다. 기존 resumable 저널과 큰 파일의 재개 방식은 유지한다.
- 폴더 경로 확인은 최소 메타데이터만 조회한다. 폴더 생성 직후·이동 직전 확인을 유지하며, 영구적인 경로 캐시를 신뢰해 변경 검사를 생략하지 않는다.
- macOS는 이미 작은 파일 multipart 및 ID 기반 경로 구조를 사용한다. Google 전용 폴더의 권한 확인과 루트 확인이 같은 메타데이터를 두 번 받던 부분을 단일 응답 검증으로 합쳤다.
- 업로드 완료는 서비스 체크섬과 최종 게시 검증을 통과해야 기록한다. 원본·백업 위치·작업 ID·기존 체크포인트는 바꾸지 않는다. 프리뷰 22에서 생성한 백업을 이어갈 수 있다.

## 검증 대상

새 파일의 선행 일괄 조회 금지, 목록 확인 후 새로 나타난 외부 파일 보존, 새 파일에 대한 불필요한 휴지통 조회 없음, 33개 소형 파일의 ID 2회 발급/업로드 33회, 응답 유실과 목록 반영 지연 중 ID로 복구, 이동된 업로드 ID 거절, 기존 대용량 재개·0바이트·중복 파일·체크섬·교체·복구·종료·재시작 회귀.

실제 처리속도 배수는 새 설치본으로 같은 작업의 완료 기록을 비교하기 전까지 확정하지 않는다. 사용자 실행 중인 백업과 인증 설정은 개발·회귀 검사에 사용하지 않는다. 일반 업데이트 목록과 Google Cloud 심사 설정은 시험이 끝날 때까지 기존 값을 유지한다.
