# Windows 1.0.0-preview.15 재시작 색인 및 폴더 충돌 수정

2026-10-22 · Horizon Entertainment · apps@horizonent.co.kr

## 수정

- 로컬 변경 저널 볼륨을 `GENERIC_READ` 읽기 전용으로 연다. 쓰기 권한, 저널 생성·삭제, 관리자 권한 강제, 서비스 설치는 추가하지 않는다. 읽기 핸들을 열 수 없으면 기존 메타데이터 핸들 호환 경로를 시도하며, 변경 기록을 확인할 수 없으면 안전한 전체 재검사를 유지한다.
- 원본에 실제 폴더가 있는 변경 이벤트는 단방향 엔진의 ‘파일 없음/삭제’ 경로에 넣지 않는다. 백업에 같은 경로의 파일이 있으면 실제 종류 충돌로 보호한다. 양쪽이 폴더이거나 백업이 없으면 잘못된 폴더 파일 행과 그 대기 경로만 정리한다. 하위 파일 스냅샷·실제 사본·휴지통은 삭제하지 않는다.
- 변경 경로의 현재 종류를 확인한다. 과거 잘못 저장한 폴더 충돌이나 파일에서 폴더로 바뀐 경로도 하위 파일을 다시 찾는다. 정상 폴더 복구를 이유로 사라진 과거 원본 파일의 삭제 보호를 해제하지 않는다.
- 파일 내용 해시, 안전 임시 복사·교체, 삭제 직전 원본/루트 재검증, 연결 장애 보호는 유지한다. NAS 감시 공백·저널 만료·권한 제한 시 필요한 전체 비교를 무조건 생략하는 수정은 아니다.

## 검증 계획 및 범위

GitHub 독립 Windows Server 2022/2025의 NTFS 가상 디스크·USN 저널·localhost SMB 공유에서 이전 실패 시나리오를 다시 실행한다. 변경 없는 두 번째 NTFS 재시작은 전체 비교·내용 검증이 없어야 한다는 조건을 추가했다. 기존 실패 조건은 그대로 유지한다.

기존 잘못된 폴더 충돌 복구, 폴더 이벤트, 하위 파일 발견, 파일/폴더 충돌, 명시적 이번 제외, 하위 사본 보존, 원본 부재 시 삭제 보호를 로컬·가상 클라우드 테스트에 추가했다. 가상 Google Drive/Dropbox는 실제 API 계정 검증이 아니다.

실제 사용자 PC의 앱·작업·계정·스냅샷은 검사 대상으로 사용하지 않는다. Windows 10/11 및 일반 사용자 권한에서의 USN 성능, 실제 NAS/Samba와 실제 Google Drive/Dropbox, 재부팅·장기간 운전은 별도 범위다.

## 확인 결과

[GitHub Actions 39634648520](https://github.com/limfrog/SafeSync/actions/runs/39634648520), 제품 수정 커밋 `98380acdb0918447f4fb6f5d9e17f88d52b99c3c`.

- 두 OS 각각 재현 검사 **95개 전부 통과**, 기존·추가 핵심 회귀 **1,030개 전부 통과**. 이전 preview.14에서 발생했던 18개 실패는 사라졌다.
- NTFS 단방향/양방향 모두 변경 없는 두 번째 재시작에서 전체 비교 없음, 비교 경로 0, 복사 0, 충돌 0, 남은 대기 0. 원본·백업 변경 저널 체크포인트가 실제로 저장됐다.
- 최초 백업 직후 첫 재시작에는 원본 전체 열거는 생략했지만 직전 자체 복사가 만든 백업 변경 기록과 저장된 감시 대기열을 확인했다. 모든 첫 재시작에서 파일 내용 읽기가 0이라고 안내하지 않는다.
- 종료 중 추가·수정·이름 변경·삭제, 양방향 백업 쪽 변경, 내용 SHA-256 목록 일치와 휴지통 보존, 같은 크기·시각으로 내용을 바꾼 파일의 검출이 계속 통과했다.
- 파일 40개 중 5개 완료 후 저장 지점에서 프로세스를 강제 종료하고 새 프로세스에서 35개를 완료했다. 이미 완료한 5개는 재교체하지 않았다. 개별 파일 전송 중 전원 차단 검사는 아니다.
- SMB 구성에서는 여전히 전체 비교가 실행되지만 변경 없는 파일 재복사 0, 잘못된 충돌 0, 남은 대기 0을 확인했다. NAS 자체 변경 이력이 없는 감시 공백을 무조건 생략하지 않는다.
- Windows 2022의 포함 런타임 및 격리 설치 페이로드에서 라이트/다크 화면 **585개**, 설치 도구 **34개**, 설치된 파일 **505개 해시**, 설치 EXE 자체 검증과 제거 검사가 통과했다. 임시 설치는 GitHub 실행 환경 안에서만 수행했다.

모의 Google Drive/Dropbox 회귀 검사는 통과했지만 실제 계정 API 동작을 재검증한 것은 아니다. 일반 사용자에게 읽기 권한이 없으면 저널 기반 속도 개선을 적용할 수 없고 전체 재검사가 남는다. 권한을 높이거나 저널 내용을 바꾸는 기능을 이번에 추가하지 않았다.

배포 문서를 포함한 최종 설치본의 추가 실행·파일 크기·SHA-256은 `PREVIEW15-PACKAGE-RESULT.md`에 기록한다. 최종 코드·검사 결과는 이 문서와 해당 실행 링크를 함께 확인한다.
