# 프리뷰 25 — 작동 로그와 초기 준비 분석

Windows 1.0.0-preview.25 / macOS 0.3.21(30), Google Drive 제한 권한 별도 시험본.

## 변경

- 실행·파일·단계·HTTP 요청·재시도 시간과 처리 결과를 컴퓨터에 JSONL로 기록한다. 초기 설정/스냅샷/증분 기록, 오프라인 변경 저널, 중단된 교체 복구, 원본 스캔, 인증 토큰 교환, 원격 카탈로그와 메타데이터 확인을 구분한다.
- 전체 비교를 선택한 조건, 첫 파일 처리 준비 완료, 첫 업로드까지의 시간을 기록한다. 상세 파일이 순환되어도 초기 준비와 실행 결과 요약은 별도 파일에 남긴다.
- 파일 참조는 세션별 임의 키를 이용한 HMAC으로 가린다. 절대 경로와 상대 경로로 들어온 같은 원본 파일의 단계는 같은 식별자로 연결한다. 인증정보·요청 URL/쿼리·계정명·실제 파일 이름/경로·본문·예외 메시지를 진단 기록에 넣지 않는다.
- 비동기 대기열 8,192건, 상세 최대 64MiB와 요약 최대 16MiB로 제한한다. 기록 과부하는 생략 수로 알리며 저장 장애가 백업을 실패시키지 않게 한다.
- 로그 분석 도구는 상세/요약의 동일 이벤트를 중복 계산하지 않으며, 초기 준비 구간과 전체 구간을 따로 표시한다. 상세 파일이 없어진 뒤에도 요약만 읽을 수 있다.
- 복사·삭제·충돌·재시도 정책, Google drive.file, 원본 안정 사본·체크섬·기존 백업 보존과 프리뷰 24의 조회 개선은 유지한다.

## 실사용 확인 범위

- 실제 실행 중인 사용자 앱을 종료하거나 업데이트하지 않았다. 사용자 백업·계정·설정·스냅샷은 변경하지 않았다.
- 이 버전으로 실제 사용자 클라우드 백업을 끝까지 재실행하거나 실제 Mac 화면을 조작하여 검증한 것은 아니다. 이번 변경은 로깅이며 실제 속도 향상 수치를 주장하지 않는다.
- 이전 실행의 준비 시간은 소급해서 만들 수 없다. 새 버전 실행 이후 기록을 모아 초기 지연과 전송 지연을 분석해야 한다.
- 기록 구간의 중첩·병렬 실행과 OS별 HTTP 측정 기준 차이, 순환/누락 가능성은 [로그 설명](OPERATION-LOGS.md)을 따른다.
- 대량 변경 보호·복원, 복원 검증, Windows VSS는 다음 목표이며 이번에 구현한 기능이 아니다. 암호화 추가는 제외한다.

최종 배포 파일의 SHA-256은 [시험본 체크섬](../dist/DRIVE-FILE-SHA256SUMS.txt)에 기록한다. 일반 자동 업데이트 목록과 Google Cloud 심사 설정은 유지한다.
