# Windows 1.0.0-preview.16 실행 중 문제 해결 예약

2026-10-22 · Horizon Entertainment · apps@horizonent.co.kr

## 동작

- 같은 작업이 동기화 중이어도 문제 해결 목록의 현재 파일 정보를 읽고 원본→백업, 백업→원본, 둘 다 보관, 이번 제외, 가능한 중복 이름 정리를 선택한다. 위치가 바뀐 옛 기록, 읽을 수 없는 파일, 파일/폴더 종류 충돌은 무조건 덮어쓰도록 풀지 않는다.
- 동기화 중에는 처리 버튼을 누르는 즉시 예약한다. 별도 ‘처리 예약’ 버튼이나 추가 확인 단계는 없다. 같은 작업의 현재 동기화 전체가 끝난 뒤 실행하며 다른 작업 전체의 완료를 기다리거나 현재 동기화를 강제 종료하지 않는다. 대기 상태의 즉시 적용은 기존 적용·확인 단계를 유지한다.
- 예약할 때 확인한 파일·루트 식별/메타데이터·클라우드 리비전과 선택한 연결에 권한을 묶는다. 자동 재시도나 수동 실행이 예약을 앞질러 같은 작업을 중복 실행하지 않도록 스케줄러 실행 소유권을 유지한다. 대기 중 확인 정보가 바뀌면 기존 파일을 보존하고 재확인을 요청한다. 전송 체크섬·교체 직전 재검사·휴지통 보존을 그대로 사용한다.
- 예약은 문제 해결 탭을 닫거나 이력을 바꿔도 유지한다. 파일별 ‘예약 · 처리 방법’, 실행 대기 파일 수와 선택 파일의 **예약 취소**를 제공한다. 실행 전 다른 버튼을 누르면 기존 예약을 바꾸고 마지막 선택만 실행한다. 이미 시작한 처리 묶음은 ‘처리 중’으로 표시하고 중간 변경·중복 예약을 차단한다.
- 현재 동기화가 파일별 오류·충돌을 남기며 완료되면 예약 처리를 시도한다. 작업 자체 실패·작업 종료·연결 변경·업데이트·앱 종료에서는 미실행 예약을 취소한다. 예약은 이번 프로그램 실행 동안만 유지하며 재시작 후 오래된 덮어쓰기 명령을 자동 복원하지 않는다. 취소는 활동 기록에 남긴다. 일시정지는 예약을 지우지 않고 해당 실행이 재개되어 끝날 때까지 기다린다.
- 대기 상태의 기존 즉시 적용·이전 이력 재비교는 유지한다. 버튼을 누르는 순간 원래 동기화가 끝났거나 예약 처리가 시작되면 변경 성공으로 오인하지 않고 현재 파일 재확인을 안내한다.

## 검증 범위

GitHub 독립 Windows 2022/2025에서 기존 재시작·회귀와 신규 예약 검사를 실행한다. 로컬·모의 Google Drive/Dropbox, 단방향/양방향에서 현재 동기화 전체 이후 실행, 마지막 버튼 우선·중복 실행 방지, 이전 사본 보관, 선택 사본의 불변성, 취소·종료·파일 변경·연결 변경·실패·업데이트·일시정지를 확인한다. 별도 격리 앱의 라이트/다크 화면에서는 실제 버튼 한 번으로 예약·다른 버튼으로 변경·파일별 상태 표시·탭 재생성·취소·재예약·후속 실행을 검사한다.

검사 결과와 최종 설치본의 SHA-256은 완료 후 별도 `PREVIEW16-PACKAGE-RESULT.md`에 기록한다. 실제 사용자 앱·백업·계정은 검사하거나 자동 업데이트하지 않는다. 클라우드 모의 검사는 실계정 API 검증이 아니며 실제 NAS·사용자 화면·장기 운전은 별도 범위다. macOS 0.3.12는 이번 Windows 변경에 포함하지 않는다.
