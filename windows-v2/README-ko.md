# SafeSync Windows 1.0.0 Preview

현재 버전은 **1.0.0-preview.1**입니다. PowerShell 실행 없이 동작하는 C#/.NET Windows 데스크톱 앱의 공개 프리뷰입니다. 이전 개발 버전의 2.0.0-preview 번호를 1.0.0 프리뷰로 재정리했습니다. 정식 안정판·코드 서명·클라우드 공개 심사 완료를 뜻하지 않습니다. 중요한 자료는 별도 사본을 보관하고 테스트 폴더에서 먼저 확인하세요. macOS 배포본은 이번 Windows 버전 변경 대상이 아닙니다.

## 1.0.0-preview.1 양방향 동기화 · Dropbox 공개 앱

- 새 작업에서 단방향 백업/양방향 동기화 선택. 기존 작업은 단방향 유지
- 양쪽 수정·삭제 전파, 마지막 성공 기준의 충돌 판정, 각 위치 휴지통과 복구
- 역방향 로컬/NAS/Google Drive/Dropbox 검증 복사 및 실패·잠김 재시도
- Dropbox `SafeSync Personal` 공개 App Key 기본 적용, 사용자별 OAuth PKCE 연결
- 전체 Dropbox 폴더 선택·생성, 실행 시 선택 경로/폴더 ID/계정 제한
- [상세 동작과 주의사항](TWOWAY-AND-DROPBOX.md). Production 승인은 별도

## preview.9 Google Drive 실계정 검증·재시작 조회 보완

- 연결된 Google 계정으로 인증 갱신·초기 백업·다운로드 내용 검증·시간 보존·증분 비교·충돌·잠금 대기·휴지통 복구/삭제·전송 재개 검사
- 원본 재확인이 유효한 Google 변경 커서까지 강제로 전체 재조회하던 경로 수정. 원본 안전 확인과 수동 전체 비교/원격 커서 만료 복구는 유지
- 실제 계정의 17개 파일 시험에서 원격 전체 열거 3회→0회, HTTP 23회→11회 확인. 모든 환경의 속도 개선을 보장하는 수치는 아님
- 앱/설치 파일의 버전을 공통 빌드 정보에서 읽어 서로 다른 버전 표시 방지
- 자세한 증거와 한계: [Google 실계정 검증 기록](GOOGLE-LIVE-RESULTS.md)

## preview.8 배포 전 안전성 검증

- 클라우드 요청 제한/일시적 조회 오류의 제한된 지수 재시도, Retry-After 및 계정별 대기 시간 공유. 권한 오류는 반복하지 않으며 응답 유실 가능성이 있는 생성/이동은 무조건 재실행하지 않음
- 신버전 스냅샷 가져오기에 native delta 반영, 이전 Generation 확장 필드 중복 직렬화 방지
- 실제 NAS의 양방향 복사·원자적 교체·잠금 대기·휴지통/복구 확인. 123개 시험 파일에 32 MiB+17바이트 대용량/빈 파일/한글·긴 경로 포함
- 별도 네이티브 설치/업데이트/제거 EXE, 파일별 체크섬, 업데이트 중 강제 종료 후 이전 버전 복구 검사
- 환경설정 최소 폭 보완, 프로그램 정보/하단 버전의 빌드 정보 자동 반영
- 500개 파일·200회 반복 변경과 실제 복사 프로세스 종료 후 재복사 검사 통과. 다일 연속 실행을 대신하지 않음
- 상세 증거와 미검증 항목: [배포 검증 현황](RELEASE-VALIDATION.md)

설치본은 `%LOCALAPPDATA%\Programs\SafeSync2`에 1.x와 별도로 설치하며 기존 1.x 데이터는 자동으로 가져오지 않습니다. 시작 메뉴의 **SafeSync 2** 또는 설치 폴더의 `SafeSync.exe`에서 실행합니다. 설치/업데이트/제거는 신버전에 안전한 종료를 요청하며 종료하지 못하면 강제 종료하지 않고 중단합니다. 업데이트는 다시 설치 EXE를 실행하는 방식이며 자동 다운로드 업데이트는 아닙니다. 제거는 설정·스냅샷·실제 백업을 보존하고, 중단된 제거 후 재설치를 위한 작은 소유 표시/설치 목록 파일을 남깁니다. 설치 부트스트랩은 Windows .NET Framework 4.8 환경을 전제로 하며 앱의 .NET 10 런타임은 포함합니다. 깨끗한 Windows 설치·등록·자동 시작 및 실제 클라우드 계정 검사는 여전히 필요합니다.

## preview.5 변경

- 독립적인 동기화 상태 창을 상단 작업 이력 표 + 선택한 실행의 상세 탭으로 정리
- 프로그램이 켜진 후의 수동·자동 실행을 각각 별도 기록. 같은 작업이 반복 실행되어도 이전 결과를 덮어쓰지 않음
- 시작·종료·경과 시간, 진행/일시정지/완료/변경 없음/오류/충돌/중단 결과, 복사·동일·휴지통·대기·충돌·오류 건수 표시
- 완료한 실행을 선택하면 당시의 원본/백업 위치와 결과·오류 파일을 확인. 이후 작업을 수정하거나 새 실행이 끝나도 과거 기록은 유지
- 진행 상세 / 충돌 / 사용 중 파일 / 오류 탭으로 분리. 진행 창에서도 선택한 실행의 일시정지·재개 가능
- 과거 충돌 기록은 읽기 전용. 현재 작업의 최신 종료 결과에서만 충돌 처리와 대기 파일 재시도 가능
- 과거 행을 선택하면 해당 상세를 유지하며, `최신 작업 보기`로 새 실행 자동 선택을 다시 활성화
- 라이트·다크 표/탭/스크롤바 일치, 좁은 창의 가로 스크롤, 이력 표와 상세 영역 사이의 드래그 분할 높이 저장

작업 이력은 **이번 실행의 메모리에만** 보관됩니다. 상태 창을 닫아도 남지만 프로그램을 완전히 종료한 뒤 다시 실행하면 새로 시작합니다. 과거 결과는 당시의 기록이며, 후속 백업에서 문제가 해결되었는지는 최신 결과를 확인하세요. 기존 작업·계정·스냅샷의 저장 위치나 백업 엔진의 파일 교체 규칙은 변경하지 않습니다.

## 실행과 데이터 보호

런타임 포함 ZIP 전체를 풀고 `SafeSync.exe`를 실행하면 알림 영역에 아이콘이 나타납니다. 아이콘을 더블클릭하면 메인창이 열립니다. 창을 닫으면 알림 영역에서 계속 실행하며, 아이콘의 **프로그램 종료**로 종료합니다. `runtime`과 `Assets` 폴더를 EXE와 함께 유지하세요. PowerShell이나 별도의 .NET 설치가 필요하지 않도록 .NET 런타임을 함께 배포합니다.

- 검증본 데이터: `%LOCALAPPDATA%\SafeSync2-Preview`
- 기존 버전 데이터: `%LOCALAPPDATA%\SafeSync` — 자동으로 읽거나 수정하지 않습니다.
- 기존 1.x가 실행 중이면 새 버전의 백업을 막습니다. 새 버전이 백업 중일 때도 기존 런처의 실행을 막아 같은 백업 위치를 동시에 변경하는 것을 방지합니다.
- 기존 설정 파일이나 작업 목록을 **파일 → 작업 목록 가져오기**에서 직접 선택할 수 있습니다. 가져온 작업은 모두 일시정지 상태입니다. 원본 설정 파일은 변경하지 않습니다.
- 기존 `config.json`을 선택하면 같은 데이터 폴더의 스냅샷·일치하는 델타 체크포인트·보호된 계정을 복사 승계합니다. DPAPI는 같은 Windows 사용자에서만 복호화할 수 있습니다. AES 대체 인증은 원본 `secrets.key`로 읽은 뒤 DPAPI로 다시 보호하며 키 파일은 복사하지 않습니다.
- 승계 자료는 새 상태 세대에 준비한 뒤 설정 포인터를 원자적으로 전환합니다. 실패하면 이전 설정·스냅샷을 유지합니다. 가져온 작업은 모두 일시정지하며 첫 실행에서 전체 메타데이터를 한 번 재확인합니다. 파일을 무조건 다시 전송하는 것은 아닙니다.
- 기존 앱에 미완료 전송/교체 기록이 있으면 가져오기를 중단합니다. 1.x 앱에서 복구를 마치고 완전히 종료한 뒤 가져오세요. 기존 전송 세션을 새 형식으로 임의 변환하지 않습니다.
- 자동 시작은 환경설정에서 선택해 등록합니다. 정확히 식별되는 표준 1.x 자동 시작 항목만 전환하며, 수동 항목은 별도 확인하세요. 기존 설치본 교체는 하지 않습니다. 검증본 종료 후 압축을 푼 앱 폴더를 정리할 수 있습니다. 실제 백업 파일은 별도 위치에 있으므로 앱 폴더와 혼동하지 마세요.

## 이번 단계에서 구현한 범위

- 기존 메인창·작업 설정·환경설정·독립 진행/충돌 창·휴지통 화면의 WPF 레이아웃 재사용
- C# 기반 로컬·외장·마운트된 네트워크 폴더 백업
- 파일 변경 감지·예약 실행, 일시정지와 같은 작업에서의 재개
- 실행 중 변경 경로를 모아 처리하는 증분 백업. 경과 일수에 따른 전체 재검사는 없음
- 재시작 시 NTFS USN으로 오프라인 변경을 수집. 미지원/권한 부족/기록 손실은 안전한 메타데이터 비교로 대체
- 원본의 시간·크기 비교, 충돌 시 다른 파일은 계속 처리
- 충돌별 덮어쓰기·기존 백업 이름 변경 후 복사·이번에는 무시 선택
- 사용 중인 파일은 일반 오류 대신 대기 목록에 표시하고 재시도
- 임시 사본 SHA-256 확인 → 원자적 교체 → 교체 후 재검증, 이전 파일 보관, 중간 종료 복구 기록
- 완료/실패/대기/충돌과 미처리 경로의 스냅샷 저장. 중단된 파일은 다음 실행에서 안전하게 재시도
- 휴지통 백그라운드 목록 조회, 다중 선택 복구·완전 삭제, 100일 기본 보관 기간
- 라이트·다크 모드, 창·분할 높이 저장, 알림음 선택, 알림 영역 실행과 회전 아이콘
- 작업 목록 내보내기·가져오기. 내보내기에 계정 정보는 포함하지 않음
- Google Drive·Dropbox 시스템 브라우저 OAuth/PKCE, 암호화된 오프라인 토큰, 계정·폴더 선택
- 8 MiB 분할 전송, 서비스 체크섬 확인(Google MD5 / Dropbox content_hash), 임시 업로드 후 기존 백업 보관·교체·재검증
- 중단된 업로드/교체 기록 복구, 세션 전송 위치 재확인, 응답 유실·체크섬 오류 시 안전한 재시도
- 클라우드 휴지통 비동기 목록·다중 복구/삭제. 진행 중 교체에 필요한 사본은 기간 정리에서 보호

## 아직 완료되지 않은 범위

1. Google 새 브라우저 로그인/공유 드라이브·조직 정책/권한 변경 시험. Google 기존 연결과 Dropbox 실제 OAuth·양방향 전송 검사는 통과했으며 전체 공개 승인과는 별개
2. 변경 피드·USN·병렬 전송·대규모 상태의 실제 환경 성능과 장시간 시험. 현재는 합성/모사 검사이며 웹훅 push 감시는 미구현
3. SQLite 인덱스 등으로 기본 스냅샷 로딩·시작/종료 정리 및 반복 폴더 ID 확인 비용 추가 최적화
4. 실제 NAS의 물리적 연결 끊김·전원 종료, 수 GB 이상 파일·장시간 실행 검증. 기본 교체/잠금/복구는 preview.8의 지정 NAS에서 확인
5. 설치/업데이트/제거의 깨끗한 Windows·실제 등록/자동 시작과 이전 버전 대비 실제 환경 전체 기능 회귀 검증. 코드 서명·Google/Dropbox 공개 승인·장시간 검증은 정식 배포 전 별도 진행

검증본의 파일 교체는 Windows 원자적 교체를 지원하지 않는 파일시스템에서 안전을 위해 실패 처리합니다. 심볼릭 링크와 연결 지점은 따라가지 않습니다. 내용이 같아 보이는 파일도 다른 프로그램의 쓰기 잠금이 있으면 대기합니다. 복구/삭제를 실행하면 해당 작업은 확인할 때까지 일시정지로 남습니다. 개별 파일 변경 처리는 데이터 안전을 우선하여 앱 내부에서 직렬화합니다.

클라우드의 두 파일 이동은 로컬 파일 교체처럼 원자적이지 않습니다. 중간에는 대상 이름이 잠시 없을 수 있으며 저널과 이전 사본으로 복구합니다. 같은 클라우드 계정의 작업·휴지통 변경은 직렬화합니다. 외부 사용자의 동시 수정을 완전히 잠글 수 없으므로 비교·재확인 중 변동이 감지되면 덮어쓰지 않고 충돌로 남깁니다. Google 문서·바로가기는 일반 파일로 덮어쓰지 않습니다. Dropbox는 개인 앱의 `delete_v2`를 사용하므로 SafeSync 휴지통에서 제거된 뒤에도 Dropbox 자체 복구 정책이 적용될 수 있습니다. 검증 실패한 임시 사본은 자동 폐기하지 않고 보존합니다.

## 클라우드 시험 방법

1. 기존 앱을 완전히 종료합니다. 새 버전은 빈 테스트 원본과 별도의 클라우드 테스트 폴더만 사용하세요.
2. 환경설정 → 클라우드 계정에서 연결하거나 기존 `config.json`을 가져옵니다. Dropbox는 포함된 기본 공개 App Key를 사용합니다(Production 승인 전 개발 사용자 한도 적용). Google은 OAuth Client ID 설정과 본인 계정 승인이 필요합니다.
3. 새 작업에서 Google Drive 또는 Dropbox를 선택하고 `위치 선택`으로 폴더를 지정합니다. 계정 ID와 폴더 참조를 작업에 함께 묶어 다른 계정으로 잘못 전송하는 것을 차단합니다.
4. 작은 테스트 파일로 최초 백업 → 내용 변경 → 충돌 처리 → 삭제/복구 → 중단 후 재실행을 확인하세요. 문제가 있으면 1.x로 되돌아가기 전에 검증본을 완전히 종료하세요.

## 개발 및 검사

.NET 10 SDK가 필요합니다. 외부 NuGet 패키지 없이 빌드합니다.

```powershell
.\scripts\Build.ps1 -RunTests
```

런타임 포함 검증 ZIP은 SDK 설치 폴더에 Windows .NET 10 런타임이 있는 환경에서 다음과 같이 만듭니다.

```powershell
.\scripts\Build.ps1 -DotnetPath 'C:\path\to\dotnet.exe' -RunTests -BundleRuntime
```

산출물은 `artifacts/`에 생성합니다. SDK 및 런타임·빌드 캐시는 저장소에 넣지 않습니다. `scripts/Extract-LegacyViews.ps1`은 최초 UI 이식용 개발 도구이며 앱 실행에 사용되지 않습니다. 이후 C# 화면 수정은 `src/SafeSync.App/Views/`에서 독립적으로 진행합니다.

사용한 로컬 개발 SDK는 Microsoft 공식 .NET 10.0.402입니다. 다운로드 SHA-512를 [공식 릴리스 메타데이터](https://dotnetcli.blob.core.windows.net/dotnet/release-metadata/10.0/releases.json)와 대조했습니다. 번들에는 공식 SDK의 .NET 10 런타임과 라이선스·제3자 고지를 포함합니다.
