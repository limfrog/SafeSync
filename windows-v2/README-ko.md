# SafeSync Windows 1.0.0 Preview

현재 Windows 수정본은 **1.0.0-preview.16**입니다. 개발자 및 운영자는 **Horizon Entertainment**, 문의 이메일은 **apps@horizonent.co.kr**입니다. 자동 백업·양방향 동기화를 제공하는 Windows 데스크톱 앱의 프리뷰이며, 정식 안정판·코드 서명·클라우드 공개 심사 완료를 뜻하지 않습니다. 중요한 자료는 별도 사본을 보관하고 테스트 폴더에서 먼저 확인하세요.

## 1.0.0-preview.16 실행 중 파일 처리 예약

동기화 중에도 문제 해결에서 현재 파일을 확인하고 덮어쓰기·역방향·둘 다 보관·이번 제외를 선택할 수 있습니다. **처리 버튼을 누르면 바로 예약**되며 별도 예약 버튼이나 확인 단계는 없습니다. 해당 작업의 현재 동기화 전체가 끝난 뒤 재검증하여 처리합니다. 실행 전에 다른 버튼을 누르면 마지막 선택으로 예약을 바꿉니다. 파일별 ‘예약 · 처리 방법’, 실행 대기 수와 **선택 예약 취소**를 확인하세요. 이미 처리 중인 예약은 바꾸지 못합니다. 대기 중 확인 정보가 바뀌면 덮어쓰지 않고 재확인을 요청합니다. 대기 상태의 즉시 적용은 기존 적용·확인을 유지합니다.

예약은 이번 앱 실행 동안 유지되며 탭 전환·일시정지로 사라지지 않습니다. 작업 종료·작업 자체 실패·연결 변경·업데이트·앱 종료 시 미실행 예약은 취소됩니다. 오래된 오류 기록으로 재시작 후 자동 덮어쓰기를 하지 않습니다. [동작과 검사 범위](PREVIEW16-VALIDATION.md)를 참고하세요.

## 1.0.0-preview.15 재시작 비교 · 폴더 충돌

NTFS 변경 기록을 읽기 전용으로 열어 재사용합니다. 변경 기록과 스냅샷이 정상이고 대기 중인 변경이 없으면 재시작 시 전체 파일을 다시 비교하지 않습니다. 폴더 이벤트를 사라진 파일로 오인하던 단방향 충돌도 수정했으며, 실제 폴더임을 확인한 과거 잘못된 항목은 하위 파일과 백업 사본을 유지한 채 정리합니다. 실제 파일/폴더 충돌, 원본 부재 시 삭제 보호와 파일 내용 검증은 유지합니다.

GitHub Windows Server 2022/2025에서 재시작·종료 중 변경·저장 지점 강제 종료 복구 95개와 핵심 회귀 1,030개를 각각 통과했습니다. 변경 없는 두 번째 NTFS 재시작에서는 비교 경로·재복사·미완료 항목이 모두 0개였습니다. 첫 재시작에는 직전 전송이 만든 변경 기록을 다시 확인할 수 있습니다. NAS 감시 공백, 저널 만료 또는 읽기 권한 부족에서는 안전한 전체 비교가 여전히 필요하며 관리자 실행을 강제하지 않습니다. 실제 NAS·클라우드 계정이나 Windows 10/11 일반 권한의 성능 검증을 완료했다는 뜻은 아닙니다. [검사 범위](PREVIEW15-VALIDATION.md)를 참고하세요.

## 1.0.0-preview.14 문제 해결 버튼

이전 동기화 이력에서도 **파일 비교 및 처리**를 열 수 있습니다. 이전 결과를 그대로 적용하지 않으며, **현재 파일 다시 비교**를 눌러 선택한 파일의 현재 정보를 읽은 뒤 덮어쓰기·역방향 복구·둘 다 보관·이번 제외를 선택합니다. 해당 작업이 실행 중이면 **현재 파일 마치고 종료**를 누르고 대기 상태가 된 뒤 다시 비교하세요. 자동 실행은 직접 작업을 다시 시작할 때까지 대기합니다.

새 동기화가 시작되거나 작업 위치·계정·방향이 바뀌면 기존 처리 권한은 무효화합니다. 다시 확인할 때 이전 선택도 지우며 적용 직전 파일과 위치를 재검증합니다. 읽을 수 없거나 파일/폴더 종류가 맞지 않는 방향은 계속 차단하고 가능한 처리만 활성화합니다. 메인 버전 표시의 ‘C#/.NET 전환 검증본’과 시작 활동기록의 과거 설정 분리 안내는 제거했습니다. 기존 데이터 경로나 호환 처리는 바꾸지 않습니다. [검사 범위](PREVIEW14-VALIDATION.md)를 참고하세요.

## 1.0.0-preview.13 앱 업데이트

환경설정에서 새 버전 자동 확인·자동 다운로드를 각각 켜고 끌 수 있다. 앱 시작 후와 매시간 GitHub의 배포 정보를 확인하며, 도움말·환경설정·알림 영역에서 수동 확인도 가능하다. 다운로드 크기와 SHA-256을 검증하며 설치는 별도의 사용자 확인 후 현재 파일을 마치고 진행한다. 기존 버전에서는 이번 설치 파일을 한 번 직접 설치해야 한다. [업데이트 사용·배포 안내](UPDATES.md)를 참고한다.

## 1.0.0-preview.12 개발자·문의 정보 통일

앱 정보, 파일 속성의 회사·저작권, 설치 프로그램의 게시자·연락처·지원 링크를 Horizon Entertainment 및 apps@horizonent.co.kr로 통일했다. 백업 엔진은 프리뷰 11과 같다. [변경 기록](PREVIEW12-VALIDATION.md)을 참고한다.

## 1.0.0-preview.11 단방향 백업 안전성 수정

- 비교 대상 파일은 크기와 수정 시각이 비슷해도 내용 체크섬을 검증한다. 내용이 다르고 어느 쪽이 최신인지 불확실하면 완료로 기록하지 않고 충돌·재시도 대상으로 남긴다. 실제 내용이 같은 파일은 기존 백업을 변경하지 않는다.
- 원본 및 로컬 백업 루트의 식별정보를 스냅샷에 저장한다. 연결 중단·폴더 교체를 확인하면 삭제 반영을 차단하고 기존 기록을 유지한다. 연결을 복구하면 재시도할 수 있다. 의도적으로 폴더를 교체했다면 기존 자료를 확인한 뒤 새 작업으로 등록해야 한다.
- 클라우드 삭제 직전 및 중단된 삭제 기록의 재처리에서도 원본 부재를 다시 확인한다. 원본이 다시 생기거나 확인할 수 없으면 기존 백업을 유지한다.
- 이전 스냅샷은 유지하며 최초 한 번 재검증한다. 따라서 업데이트 후 첫 비교와 수동 전체 비교는 종전보다 오래 걸릴 수 있다. 평상시에는 변경·재시도 대상만 처리한다. 구버전에서 삭제되어 현재 원본을 확인할 수 없는 파일은 자동 삭제하지 않고 검토 대상으로 남긴다.
- 실제 NAS·클라우드 장애 재현과 장기간 연속 운전은 별도 검증 대상이다. 자세한 이번 검사 결과는 `PREVIEW11-VALIDATION.md`에 기록한다.

## 1.0.0-preview.10 공통 환경설정 · 작업 도구 정렬

- 백업 작업 탭의 중복된 ‘휴지통 관리’와 ‘동기화 상태’ 버튼을 제거했다. 해당 기능은 기존 상단 탭 또는 보기 메뉴로 이동한다.
- 환경설정 아이콘을 탭 제목줄 오른쪽 공통 영역으로 옮겼다. 백업 작업·동기화 상태·휴지통 어느 탭에서도 보이며 같은 환경설정 창을 연다. 설정을 닫으면 선택한 탭을 유지한다.
- 작업 관리는 왼쪽의 ‘새 작업’ 옆에 배치했다. 생성·관리와 실행·일시정지·모든 작업을 구분선으로 묶고 모든 버튼을 왼쪽 정렬했다.
- 공통 탭 제목줄은 환경설정 자리 48픽셀을 별도로 확보하여 탭과 겹치지 않는다. 라이트/다크 및 800×540·1180×720에서 정렬·표시·실제 설정 열기/닫기를 검사한다. 동기화 엔진·계정·스냅샷 형식은 변경하지 않았다.

## 1.0.0-preview.9 한 창의 작업 공간 · 중복 경로 복구

- 메인창의 백업 작업 / 동기화 상태 / 휴지통 관리 탭으로 이동한다. 동기화 상태와 휴지통은 별도 최상위 창을 표시하지 않는다. 동일한 휴지통 탭 재방문은 표시 중인 목록을 유지하고 다른 작업의 휴지통으로 바꿀 때 이전 조회를 취소한다. 복구·삭제 중에는 대상 교체를 막지만 다른 탭은 사용할 수 있다. 설정·로그인·확인 대화상자는 별도 화면을 유지한다.
- 메인 문제 해결 아이콘을 제거했다. 작업 메뉴, 작업 상태 더블클릭, 동기화 결과 또는 오류·충돌 목록에서 동기화 상태의 하단 문제 해결로 들어간다.
- 작업 목록과 활동기록 사이 막대를 위아래로 드래그한다. 명시적인 Rows/PreviousAndNext 분할이며 높이를 저장한다. 작은 메인창에서도 최소 로그 영역과 상태줄을 확보하고 과도한 저장 높이는 현재 크기에 맞춘다. 작은 동기화·휴지통 탭은 바깥 스크롤로 전체 조작부에 접근한다.
- Google Drive에 같은 이름의 폴더가 여러 개 있어도 읽기 비교는 물리 ID별로 하위 항목을 확인한다. 파일 이름·크기·생성일시만으로 동일성을 확정하지 않고 모든 해당 사본의 내용 체크섬이 원본과 같은 경우 복사 없이 BackedUp으로 기록한다. 양방향에서는 이 상태를 삭제 전파 권한으로 사용하지 않는다. 중복 폴더의 ID와 변경 피드가 그대로라면 하위 트리를 매 실행 다시 열지 않는다.
- 다른 중복 사본은 하단 문제 해결에서 경로별 사본 ID·크기·생성/수정일시를 확인한 뒤 네 방향 선택을 적용한다. ID 순서의 첫 사본을 현재 백업으로 표시하며 나머지는 확인 후 `.SafeSync-conflict-...` 이름으로 보존한다. 폴더의 경우 내부 파일 전체가 바뀐 폴더 이름 아래 남으며 삭제하지 않는다. ‘중복 이름만 정리 · 사본 모두 보존’은 내용 방향을 강제하지 않고 중복 경로를 풀어 재비교한다. 보존된 이름은 일반 파일·폴더이므로 이후 양방향 작업에서 원본으로 복사될 수 있다.
- 수동 적용은 계정 단위 실행 잠금 안에서 선택 전체의 원본·백업·루트·사본 집합을 다시 검증한다. 비교 이후 변경이 있으면 중단한다. 중복 사본 이름 보존 후 기존 검증 전송·안전 교체·휴지통·역방향 체크섬 절차를 사용한다. 이름 변경 중 중단되어도 파일 내용은 기존 이름 또는 보존 이름에 남는다. 서로 다른 파일/폴더가 한 경로에 섞인 경우에는 강제 파일 교체를 허용하지 않는다.

## 1.0.0-preview.8 동기화 상태 하단 문제 해결

- 별도 ‘문제 해결’/‘파일 비교’ 창을 없애고 동기화 상태 창 아래쪽 ‘문제 해결’ 탭에 통합했다. 위쪽 작업 이력을 선택하면 아래 내용이 그 작업을 따라간다. 메인창의 문제 해결, 결과의 해결 버튼, 오류·충돌 파일 비교도 이 영역으로 이동한다.
- 하단 왼쪽은 오류·충돌 파일 목록, 오른쪽은 원본/백업 정보와 네 가지 처리 선택이다. ‘작업 연결 · 오류 해결’을 선택하면 같은 공간에서 오류 원문·해결 안내·재시도·계정 연결·백업 위치 다시 연결·작업 설정·일단 대기를 사용한다. 필요 시 계정 로그인/설정 자체와 휴지통은 기존 별도 화면을 사용한다.
- 과거 이력은 읽기 전용이며 현재 작업의 재시도·교체 권한으로 재사용하지 않는다. 다른 작업/이력/설정으로 바꾸면 기존 파일 처리 선택과 비동기 조회를 해제한다. 같은 이력의 단순 진행 갱신 및 창 숨김/다시 표시에서는 선택을 보존한다.
- 작은 창에서는 비교 상세와 해결 안내를 스크롤할 수 있으며 파일 처리 버튼은 하단에 유지한다. 위쪽 이력과 아래쪽 영역은 기존 구분선으로 높이를 조절하고 저장한다. 문제 해결 탭에서는 중복된 작업 위치 요약을 접어 공간을 확보한다.
- 앱 재시작 후 이번 실행 이력이 없는 저장된 오류도 현재 작업의 하단 안내에서 재시도할 수 있다. 안전 복사·역방향 복원·체크섬·휴지통 동작은 preview.7 엔진을 유지한다. 아래는 이전 버전 개발 이력이다.

## 1.0.0-preview.7 파일 비교 및 처리

- 동기화 상태 창의 ‘충돌’/‘오류’ → ‘파일 비교 및 처리’ 또는 파일 더블클릭, 문제 해결 화면의 같은 버튼으로 독립 비교 창을 연다. 메인창과 다른 작업은 계속 사용할 수 있다.
- 왼쪽은 원본, 오른쪽은 백업이다. 각각 파일 전체 위치·크기·생성일시·수정일시와 존재/접근 상태를 표시한다. 정보를 읽을 수 없거나 서비스에서 생성일시를 제공하지 않으면 확인 불가/제공되지 않음으로 구분한다.
- 왼쪽 → 오른쪽 덮어쓰기, 오른쪽 → 왼쪽 덮어쓰기, 기존 백업 이름 변경 후 원본 복사(둘 다 보관), 이번 동기화에서 제외를 선택하고 확인 후 적용한다. 여러 파일을 Ctrl/Shift로 선택해 같은 방법을 지정할 수 있다.
- 단방향 작업에서도 명시적으로 선택한 파일의 백업 → 원본 복원을 지원하지만 작업의 자동 동기화 방향은 바꾸지 않는다. 기존 원본/백업은 안전 교체 시 SafeSync 휴지통으로 보관한다. 둘 다 보관은 기존 백업을 같은 폴더에 `.SafeSync-conflict-날짜-식별자` 이름으로 남긴다.
- 비교 창의 ‘원본 휴지통’에서 역방향 복원 전 원본 사본을 확인·복구할 수 있다. 일반 휴지통 창에서도 단방향/양방향 구분 없이 원본 휴지통으로 이동할 수 있다. 원본 쪽 교체 복구 기록도 재시작 시 확인하고 보관 기간을 적용한다.
- 파일 정보는 비동기로 읽는다. 적용 직전 파일·계정·폴더가 비교한 내용과 같은지 다시 확인한다. 복원 다운로드는 서비스 체크섬으로 검증한 뒤 기존 SHA-256 안전 교체 절차를 사용한다. 변경·체크섬 오류·파일 잠금은 기존 사본을 유지하고 다시 확인할 항목으로 남긴다.
- 이전 실행 결과는 읽기 전용이다. 현재 작업 실행 중에는 수동 파일 처리를 적용하지 않는다. 이름이 중복된 클라우드 항목은 임의 선택/덮어쓰기를 금지하고 연결·권한 문제 해결로 안내한다. 이번 동기화 제외는 영구 제외가 아니므로 다음 실행에서는 다시 확인한다.

## 1.0.0-preview.6 실패 후 해결 · 재시도

- 동기화 상태 창의 최신 실패 결과에도 ‘실패 원인 / 해결’과 ‘이 작업 다시 시도’를 표시한다. 과거 실행 기록에서는 현재 작업의 재시도를 실행하지 않는다.
- 해결 화면에는 오류 원문·문제 경로·원본/백업 위치와 오류별 안내를 표시한다. 재시도, 백업 위치 열기, 충돌 처리 보기, 작업 설정, 일단 대기를 제공하며 클라우드는 계정 연결/위치 다시 연결도 제공한다. 실제 파일을 임의 삭제하거나 권한을 변경하지 않는다.
- 해결 화면은 메인창을 막지 않는다. 작업 실행 중에는 중복 재시도와 설정 변경을 막으며, 재시도 결과를 화면에 갱신한다. ‘일단 대기’는 일시정지가 아닌 종료 대기이고 미처리 작업/스냅샷은 유지한다.
- 메시지를 비워도 원인·해결 정보는 별도로 보존하며 앱 재시작 후에도 확인할 수 있다. 정상 백업이 끝나면 해당 작업의 문제 표시를 해제한다. 작업 수준 실패가 반복될 때 비운 메시지가 다시 쌓이던 표시 키 불일치도 수정했다.
- 수정은 새 설치본으로 업데이트한 뒤 적용된다. 현재 실행 중인 구버전은 빌드만으로 바뀌지 않는다.

## 1.0.0-preview.5 연결 복구 · 메시지 관리

- 작업 목록을 가져온 클라우드 작업, 바뀐 계정·루트 폴더는 사용자 확인 전 자동 재시도를 막고 ‘클라우드 연결 확인 필요’로 표시한다. ‘작업 → 클라우드 위치 다시 연결’ 또는 ‘지금 백업’에서 계정·폴더를 확인해 다시 시작한다. 취소하면 기존 설정을 유지한다.
- 다시 연결하면 새 작업 ID/스냅샷으로 비교한다. 기존 설정 백업·스냅샷·미완료 전송 기록은 보존하며 새 계정·폴더에 이전 삭제 판단을 재사용하지 않는다. 양방향 첫 실행은 합집합이며 내용 차이는 충돌로 남긴다.
- 클라우드의 같은 이름 중복은 해당 경로·하위 경로·삭제 위험이 있는 상위 폴더를 충돌로 보호하고 다른 파일의 처리는 계속한다. 중복 중 어느 사본을 선택할지 임의로 정하지 않는다. 클라우드에서 중복 이름을 정리하면 다음 비교에서 해제한다.
- 확인할 메시지는 독립 창의 표로 표시하며 ‘표시한 메시지 비우기’를 제공한다. 백업 오류·충돌·파일 자체는 바꾸지 않으며 미해결 같은 메시지는 재시도/재시작에도 다시 알리지 않는다. 해결 후 재발한 오류나 새로운 오류는 다시 표시한다.
- 시작 메뉴 표시 이름을 ‘SafeSync’로 정리한다. 기존 ‘SafeSync 2’ 바로 가기는 이 앱 소유일 때만 제거한다. 다른 프로그램 바로 가기와 충돌하면 SafeSync 하위 폴더를 사용한다. 설치·설정의 내부 경로는 호환성을 위해 그대로 유지한다.

## 1.0.0-preview.3 비교 오판 · 작업 종료

- 로컬/NAS 단방향은 크기·수정 시각이 같으면 생성 시각 차이만으로 충돌을 만들지 않는다. 생성 시각은 NAS나 복사 과정에서 달라질 수 있다.
- 크기가 같고 수정 시각이 다른 파일은 로컬 SHA-256 또는 클라우드 서비스 체크섬으로 내용이 같은지 추가 확인한다. 같으면 원본·백업 파일을 변경하지 않고 건너뛴다. 실제 내용·크기가 다른 충돌은 유지한다.
- ‘작업 → 작업 종료’ 또는 ‘작업 관리 → 작업 종료’: 이미 처리 중인 파일의 검증·교체를 안전하게 마친 뒤 나머지는 중단한다. 동시 전송이 이미 시작된 파일들은 마무리한다. 비교·대기 단계는 다음 안전 경계에서 중단한다.
- 종료 대기는 재시작 후에도 유지하고 감시·예약·자동 재시도는 실행하지 않는다. 남은 경로와 스냅샷은 보존한다. ‘지금 백업’ 또는 ‘다시 시작’을 눌러야 재개한다. 일시정지는 같은 실행 안에서 멈췄다 이어가는 별도 기능이다.
- Google Drive의 브라우저 OAuth 로그인은 이미 구현되어 있다. 사용자별 키 입력을 없애는 공통 등록 앱 배포에는 제작자 OAuth 클라이언트 설정·공개 검증이 별도로 필요하다. 계정 식별 정보가 없는 이전 작업은 연결된 계정에서 폴더를 다시 선택해 계정·위치를 확인해야 하며 임의로 계정을 붙이지 않는다.

## preview.8 배포 전 안전성 검증

- 클라우드 요청 제한/일시적 조회 오류의 제한된 지수 재시도, Retry-After 및 계정별 대기 시간 공유. 권한 오류는 반복하지 않으며 응답 유실 가능성이 있는 생성/이동은 무조건 재실행하지 않음
- 신버전 스냅샷 가져오기에 native delta 반영, 이전 Generation 확장 필드 중복 직렬화 방지

- 별도 네이티브 설치/업데이트/제거 EXE, 파일별 체크섬, 업데이트 중 강제 종료 후 이전 버전 복구 검사
- 환경설정 최소 폭 보완, 프로그램 정보/하단 버전의 빌드 정보 자동 반영
- 500개 파일·200회 반복 변경과 실제 복사 프로세스 종료 후 재복사 검사 통과. 다일 연속 실행을 대신하지 않음
- 상세 증거와 미검증 항목: [배포 검증 현황](RELEASE-VALIDATION.md)

설치본은 `%LOCALAPPDATA%\Programs\SafeSync2`에 1.x와 별도로 설치하며 기존 1.x 데이터는 자동으로 가져오지 않습니다. 시작 메뉴의 **SafeSync** 또는 설치 폴더의 `SafeSync.exe`에서 실행합니다. 설치/업데이트/제거는 신버전에 안전한 종료를 요청하며 종료하지 못하면 강제 종료하지 않고 중단합니다. 업데이트는 다시 설치 EXE를 실행하는 방식이며 자동 다운로드 업데이트는 아닙니다. 제거는 설정·스냅샷·실제 백업을 보존하고, 중단된 제거 후 재설치를 위한 작은 소유 표시/설치 목록 파일을 남깁니다. 설치 부트스트랩은 Windows .NET Framework 4.8 환경을 전제로 하며 앱의 .NET 10 런타임은 포함합니다. 깨끗한 Windows 설치·등록·자동 시작 및 실제 클라우드 계정 검사는 여전히 필요합니다.

## 실행과 데이터 보호

런타임 포함 ZIP 전체를 풀고 `SafeSync.exe`를 실행하면 알림 영역에 아이콘이 나타납니다. 아이콘을 더블클릭하면 메인창이 열립니다. 창을 닫으면 알림 영역에서 계속 실행하며, 아이콘의 **프로그램 종료**로 종료합니다. `runtime`과 `Assets` 폴더를 EXE와 함께 유지하세요. PowerShell이나 별도의 .NET 설치가 필요하지 않도록 .NET 런타임을 함께 배포합니다.

- 검증본 데이터: `%LOCALAPPDATA%\SafeSync2-Preview`
- 기존 버전 데이터: `%LOCALAPPDATA%\SafeSync` — 자동으로 읽거나 수정하지 않습니다.
- 기존 1.x가 실행 중이면 새 버전의 백업을 막습니다. 새 버전이 백업 중일 때도 기존 런처의 실행을 막아 같은 백업 위치를 동시에 변경하는 것을 방지합니다.
- 기존 설정 파일이나 작업 목록을 **파일 → 작업 목록 가져오기**에서 직접 선택할 수 있습니다. 가져온 작업은 모두 일시정지 상태입니다. 원본 설정 파일은 변경하지 않습니다.
- 기존 `config.json`을 선택하면 같은 데이터 폴더의 스냅샷·일치하는 델타 체크포인트·보호된 계정을 복사 승계합니다. DPAPI는 같은 Windows 사용자에서만 복호화할 수 있습니다. AES 대체 인증은 원본 `secrets.key`로 읽은 뒤 DPAPI로 다시 보호하며 키 파일은 복사하지 않습니다.
- 승계 자료는 새 상태 세대에 준비한 뒤 설정 포인터를 원자적으로 전환합니다. 실패하면 이전 설정·스냅샷을 유지합니다. 가져온 작업은 모두 일시정지하며 첫 실행에서 전체 메타데이터를 한 번 재확인합니다. 파일을 무조건 다시 전송하는 것은 아닙니다.
- 기존 앱에 미완료 전송/교체 기록이 있으면 가져오기를 중단합니다. 1.x 앱에서 복구를 마치고 완전히 종료한 뒤 가져오세요. 기존 전송 세션을 새 형식으로 임의 변환하지 않습니다.
- 자동 시작은 환경설정에서 선택해 등록합니다. 정확히 식별되는 표준 1.x 자동 시작 항목만 전환하며, 수동 항목은 별도 확인하세요. 기존 설치본 교체는 하지 않습니다. 검증본 종료 후 압축을 푼 앱 폴더를 정리할 수 있습니다. 실제 백업 파일은 별도 위치에 있으므로 앱 폴더와 혼동하지 마세요.

- 작업 목록 내보내기·가져오기. 내보내기에 계정 정보는 포함하지 않음

- 8 MiB 분할 전송, 서비스 체크섬 확인(Google MD5 / Dropbox content_hash), 임시 업로드 후 기존 백업 보관·교체·재검증
- 중단된 업로드/교체 기록 복구, 세션 전송 위치 재확인, 응답 유실·체크섬 오류 시 안전한 재시도

## 아직 완료되지 않은 범위

1. Google 새 브라우저 로그인/공유 드라이브·조직 정책/권한 변경 시험. Google 기존 연결과 Dropbox 실제 OAuth·양방향 전송 검사는 통과했으며 전체 공개 승인과는 별개
2. 변경 피드·USN·병렬 전송·대규모 상태의 실제 환경 성능과 장시간 시험. 현재는 합성/모사 검사이며 웹훅 push 감시는 미구현
3. SQLite 인덱스 등으로 기본 스냅샷 로딩·시작/종료 정리 및 반복 폴더 ID 확인 비용 추가 최적화
4. 실제 NAS의 물리적 연결 끊김·전원 종료, 수 GB 이상 파일·장시간 실행 검증. 기본 교체/잠금/복구는 preview.8의 지정 NAS에서 확인
5. 설치/업데이트/제거의 깨끗한 Windows·실제 등록/자동 시작과 이전 버전 대비 실제 환경 전체 기능 회귀 검증. 코드 서명·Google/Dropbox 공개 승인·장시간 검증은 정식 배포 전 별도 진행

검증본의 파일 교체는 Windows 원자적 교체를 지원하지 않는 파일시스템에서 안전을 위해 실패 처리합니다. 심볼릭 링크와 연결 지점은 따라가지 않습니다. 내용이 같아 보이는 파일도 다른 프로그램의 쓰기 잠금이 있으면 대기합니다. 복구/삭제를 실행하면 해당 작업은 확인할 때까지 일시정지로 남습니다. 개별 파일 변경 처리는 데이터 안전을 우선하여 앱 내부에서 직렬화합니다.

클라우드의 두 파일 이동은 로컬 파일 교체처럼 원자적이지 않습니다. 중간에는 대상 이름이 잠시 없을 수 있으며 저널과 이전 사본으로 복구합니다. 같은 클라우드 계정의 작업·휴지통 변경은 직렬화합니다. 외부 사용자의 동시 수정을 완전히 잠글 수 없으므로 비교·재확인 중 변동이 감지되면 덮어쓰지 않고 충돌로 남깁니다. Google 문서·바로가기는 일반 파일로 덮어쓰지 않습니다. Dropbox는 개인 앱의 `delete_v2`를 사용하므로 SafeSync 휴지통에서 제거된 뒤에도 Dropbox 자체 복구 정책이 적용될 수 있습니다. 검증 실패한 임시 사본은 자동 폐기하지 않고 보존합니다.

## 클라우드 시험 방법

1. 기존 앱을 완전히 종료합니다. 새 버전은 빈 테스트 원본과 별도의 클라우드 테스트 폴더만 사용하세요.
2. 환경설정 → 클라우드 계정에서 연결하거나 기존 `config.json`을 가져옵니다. Dropbox는 포함된 기본 공개 App Key를 사용합니다(Production 승인 전 개발 사용자 한도 적용). Google은 OAuth Client ID 설정과 본인 계정 승인이 필요합니다.
3. 새 작업에서 Google Drive 또는 Dropbox를 선택하고 `위치 선택`으로 폴더를 지정합니다. 계정 ID와 폴더 참조를 작업에 함께 묶어 다른 계정으로 잘못 전송하는 것을 차단합니다.
4. 작은 테스트 파일로 최초 백업 → 내용 변경 → 충돌 처리 → 삭제/복구 → 중단 후 재실행을 확인하세요. 문제가 있으면 1.x로 되돌아가기 전에 검증본을 완전히 종료하세요.

## 개발 및 검사

.NET 10 SDK가 필요합니다. 외부 NuGet 패키지 없이 빌드합니다.

```powershell
.\scripts\Build.ps1 -RunTests
```

런타임 포함 검증 ZIP은 SDK 설치 폴더에 Windows .NET 10 런타임이 있는 환경에서 다음과 같이 만듭니다.

```powershell
.\scripts\Build.ps1 -DotnetPath 'C:\path\to\dotnet.exe' -RunTests -BundleRuntime
```

산출물은 `artifacts/`에 생성합니다. SDK 및 런타임·빌드 캐시는 저장소에 넣지 않습니다. `scripts/Extract-LegacyViews.ps1`은 최초 UI 이식용 개발 도구이며 앱 실행에 사용되지 않습니다. 이후 C# 화면 수정은 `src/SafeSync.App/Views/`에서 독립적으로 진행합니다.

사용한 로컬 개발 SDK는 Microsoft 공식 .NET 10.0.402입니다. 다운로드 SHA-512를 [공식 릴리스 메타데이터](https://dotnetcli.blob.core.windows.net/dotnet/release-metadata/10.0/releases.json)와 대조했습니다. 번들에는 공식 SDK의 .NET 10 런타임과 라이선스·제3자 고지를 포함합니다.
